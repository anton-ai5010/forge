# Формат «Гайд по проекту» (Phase 5)

Один живой версионный документ о проекте для читателя со стороны — партнёра, инвестора, нового исполнителя, самого владельца через месяц. Написан на «вы», без жаргона (термины — в словарике 08); в шапке видно, для кого он и какая версия проекта. Эталон — «Vespera — гайд по продукту и решения на утверждение» (сентябрь 2026), копия без картинок: `.forge/tasks/2026-09-06-project-guide/reference-vespera-guide.html`. Собирает его скилл `project-guide` (`/forge:guide`); HTML руками не пишется — его строит `skills/project-guide/render.py`, там же живёт канонический CSS (A4 под печать, Playfair Display + Golos Text с системным фолбэком, только светлая тема, без JS).

**Разделы по порядку:** шапка (буква-логотип · проект · «для кого» · дата · версия проекта) и строка-состояние → `00` «Где мы сейчас — за 30 секунд»: 3–5 фактов, 🔥 «Решения, без которых стоим» (только неотвеченные коды), «как работать с документом» с легендой групп и примером ответа, «Что изменилось с vX.Y» из changelog → `01` «Что это такое»: одной фразой + схема 4–6 коробок + экраны → `02` «Из чего состоит» → `03` «Главный путь по шагам» → `04` «Кто и что делает» → `05` «Решения» по группам, с кодом, «что» и «почему» → `06` «Карта рисков» по ярусам с «предлагаем» → `07` «План»: сейчас → дальше → позже → `08` «Словарик» → футер «гайд vX.Y от … · собрано из: …». Пустой раздел печатается как «раздел появится в следующей версии».

## Данные

Одна версия = один файл `.forge/guide/vX.Y.json` (память проекта, уезжает в git через memory-backup); последняя версия — максимум по имени файла, других служебных JSON нет. Схема — в docstring `render.py` и в Шаге 4 скилла, образец — `tests/hooks/fixtures/guide-sample.json`. Витрина — `docs/guide/guide-vX.Y.html`, `guide-vX.Y.pdf` (Chrome headless; нет Chrome — только HTML) и `guide-latest.html` (побайтовая копия последней версии; PDF-копии нет). Режимы рендерера: `bump [major]` · `render` · `pdf` · `verdict <код> <статус> [текст]` · `merged <slug>` · `link <id> <slug>` · `summary`; служебные строки — с префиксом `FORGE-GUIDE:`.

## Коды, статусы, версии

| Что | Правило |
|---|---|
| Риск `R<n>` | Из `id` находки: `f7` → `R7`, отдельно не пишется. Ярус — по `block`: `crit` → 🔴, `biz` → 🟠, `imp`/`pol` → 🟡. Статусы находки: `open` / `done` / `deferred`; `owner`: `code` / `decision` / `both`; `effort`: S / M / L / `-`. Находка-решение, вынесенная в вопрос `O<n>`, получает `links: ["O<n>"]` + `deferred` и «отложенной» не считается. Под риском — «→ в работе» / «→ уже работает» (задача связана через `link`/`merged`). |
| Группы решений | `P` (процесс, всегда; `P1` «Правило дефолта» обязателен) … буквы под проект (одна латинская заглавная, не P/O/R; Клод подбирает и объявляет в «как работать с документом») … `O` (открытые вопросы, всегда). Код — `^[A-Z]\d+$`, кириллица в JSON запрещена — рендерер печатает ⚠, не прерываясь. |
| Стабильность | Коды и `id` не меняются и не переиспользуются между версиями; новое — следующий номер с конца группы. Потерявшее смысл решение → `dropped`: код занят, в документе не печатается. |
| Статусы решения | `default` (метка «дефолт» — наша рекомендация: нет возражений — действуем, см. P1), `accepted` («принято»), `changed` («переделано»), `discuss` («обсудить»), `open` («открыто»), `works` («уже работает» — только проверенное), `dropped`. Метка 🔥 — `fire: true` при статусе не из `accepted|changed|works|dropped`. |
| Ответ владельца | В чате: «A2 ок», «B1 — переделать: …», «D2 обсудить», «R4 приоритет выше». Слова читает Клод, рендерер получает `verdict <код> <статус> [текст]` — один код за вызов, кириллицу в коде переводит сам. Решения: `accepted [текст]` / `changed <текст>` / `discuss` / `works` / `dropped`; риски `R<n>`: `agreed` (предложение принято, 🔥 снят) / `done` / `up` / `down` / `deferred` / `changed <текст>`. Принятое Клод пишет в `decisions.yml`. |
| Счётчики | В документе «ждут ответа» = решения `default|open|discuss`. Напоминание при старте сессии («📖 Гайд по проекту vX.Y: ждут N решений владельца, гайд устарел на M задач») считает строже: `open|discuss` + `default` с 🔥 + открытые находки с `owner: decision|both` — P1 и дефолты без 🔥 не нагоняют. |
| Версии | «Собери гайд» → `bump` = +0.1 (после 1.9 — 1.10); крупный номер только по слову («это версия 2» → v(X+1).0). `bump` копирует последнюю версию, переносит накопленные `pending_changes` в `changelog[0].items`, ставит `built_at: null` («не собрана» — такую не поднимают, а дособирают); `render` ставит в `built_at` дату сборки. Старые `vX.Y.*` никогда не правятся. Ответы (`verdict`) и мержи (`merged`) меняют последний `vX.Y.json` на месте — номер тот же, `pending_changes` + `updated_at`, обе HTML перерисованы (PDF — если уже был), в футере «обновлён …: N изменений после сборки · гайд устарел на M задач». |

## Экраны и бюджет

Не больше 6 снимков на версию, каждый PNG ≤ 200 КБ — это правило скилла (`browser_resize` 1280×800, `scale: css`, не fullPage; тяжелее — снимок не берётся): рендерер встраивает картинки в HTML как `data:` URI как есть и **не уменьшает**. Файлы — `.forge/guide/shots/` (строка `guide/shots/` в `.forge/.gitignore`: через git не едут, живут внутри HTML), у каждого снимка подпись `caption`. Telegram-бот — `tg_mocks[]` (≤2 диалога по ≤6 пузырей) из настоящих текстов бота, найденных в коде; подпись «воспроизведение сообщений бота, данные вымышленные» рендерер ставит сам. Показывать нечего — гайд без картинок, без вопросов владельцу.

## Откуда наполнение

Шесть субагентов одним сообщением: Картограф А (потоки → `01` схема, `03` путь) и Картограф Б (части, роли, словарь → `02`, `04`, `08`; дыры → находки) — по образцу product-mapping, `.forge/product-map.json` только подсказка; Аналитики 1–3 (код / git / инфраструктура + «Адреса интерфейса» для снимков) → `06` риски и `07` план; Аналитик 4 (память, документация, решения: `decisions.yml` → `accepted`, `direction.yml` и открытые задачи → `decisions[]` с кодами и группами, открытые вопросы → `O*`). Прошлая версия `vX.Y.json` — основа: коды и `id` переносятся, правится только изменившееся, разница уходит в changelog. Первый `bump` без версий создаёт `v1.0` с P1 и сам переносит старый отчёт (`.forge/status-report.json`: находки и снимки), старые файлы убирает.
