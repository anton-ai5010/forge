# Формат «Что дальше» — статус-отчёт по проекту

Эталон: артефакт «Vespera · Что дальше» (сентябрь 2026). Документ отвечает нетехнарю-владельцу на один вопрос: **в каком состоянии проект и что делать дальше, в каком порядке и почему**. Публикуется как HTML-артефакт, читается за 3–5 минут.

## Главные принципы (важнее вёрстки)

1. **Ось деления — владелец действия, а не техническая категория.** Каждый пункт помечен: «Код» (чинит Клод, решений не требует) / «Решение» (решает юзер: деньги, люди, легал) / «Решение+код». Юзер сразу видит, что из списка — его работа.
2. **Порядок — по боли, не по заметности.** Первым идёт то, без чего сервис не выполняет главную функцию. Формула проговаривается прямо в лиде: «порядок — по тому, что мешает сервису работать, а не по тому, что заметнее».
3. **Один вывод наверху.** Сразу после шапки — блок «Главное одной фразой»: самая опасная дыра / самый важный факт, 3–4 предложения. Если юзер прочтёт только это — он уже знает, с чего начинать.
4. **Язык нетехнаря, последствия вместо терминов.** «Зачем» каждого пункта — что сломается в жизни: «клиент молча повисает, тихий слив», а не «нет обработки edge case». Технический термин допустим только с переводом («Telegram вернёт ошибку 403 — уведомление уйдёт в никуда»).
5. **Честные числа.** Сколько находок всего, во сколько блоков свёрнуто, сколько отложено — в мета-строке и футере. Ничего не прячется молча: отложенное названо и посчитано.
6. **Убывающая детализация.** Критичный блок — карточки с «Что:» и «Зачем:». Средний блок — карточки в один абзац без лейблов. Отложенное — одно перечисление в футере. Объём текста пропорционален важности.
7. **От первого лица, на «ты».** «Свёл в приоритеты», «чиню я», «решаешь ты с Владом». Это разговор Клода с владельцем, не канцелярский отчёт.

## Структура документа (по порядку)

### 1. Шапка `.head`
- **Eyebrow** (mono, uppercase): позиция документа в процессе — «Дорожная карта · перед визуальным полишем».
- **H1**: человеческая формулировка вопроса документа с именем проекта — «Vespera: что доделать, прежде чем наводить красоту». Не «Отчёт о состоянии проекта».
- **Лид-абзац** (2–3 предложения): откуда данные («восемь аналитиков прошли по коду, спеке и записи созвона и нашли 71 пробел»), что с ними сделано («свёл в приоритеты»), ось деления жирным («**что чиню я в коде** и **что решаешь ты**»), принцип порядка.
- **Мета-строка**: дата · свёртка счётчиком («71 находка → 4 блока») · что идёт после этого документа («Фаза 3 (полиш) — после этого»).

### 2. Вердикт `.verdict`
Карточка с красной левой планкой, заголовок «Главное одной фразой». Один самый важный вывод, развёрнутый простым языком, ключевые слова жирным. Заканчивается указанием, откуда начинать: «Это перевешивает любой визуальный полиш — начинать надо отсюда».

### 3. Блоки приоритетов (2–4 секции `.phase`)
Каждый блок:
- Цветной тег «Блок N» + **заголовок-принцип, не категория**: «Кровь из носа — чиню в коде», «Бизнес-решения — нужны от тебя и Влада», «Скоро — усиливает продукт». В заголовке уже видно и срочность, и владельца.
- Подзаголовок одной строкой: что означает попадание сюда + кто делает («Без этого сервис не выполняет свою главную функцию. Всё — моя работа, решений не требует»).
- Сетка карточек `.grid`.

Цветовая семантика тегов: красный `crit` — критичный код; фиолетовый `biz` — бизнес-решения; янтарный `imp` — скоро/усиление; зелёный `pol` — полиш/потом.

### 4. Карточка задачи `.card`
- **Chip** владельца: `Код` (красный фон) / `Решение` (фиолетовый) / `Решение+код`.
- **Заголовок**: суть по-человечески («Партнёр может вернуть задачу в пул»).
- **Бейдж усилий** `S / M / L`; для чистых решений — «—».
- Тело в критичном блоке — два абзаца с жирными лейблами:
  - `Что:` — конкретная механика, что будет сделано/решено.
  - `Зачем:` — что ломается без этого, в терминах последствий для клиента/бизнеса.
  - В блоке решений лейбл — `Что решить:` (один абзац).
- Тело в блоке «Скоро» — один абзац без лейблов.

### 5. Футер `.foot`
Mono, приглушённый. Две вещи: (а) что осталось за кадром с числом («Блок 4 „Потом“ — 12 находок, не срочно») и парой примеров в скобках; (б) рекомендация порядка одним предложением: «сначала **Блок 1** (…критично), параллельно собрать ответы **Блока 2**, затем полиш».

## Дизайн

- **Шрифты** (Google Fonts): Archivo 500–800 — заголовки; IBM Plex Sans 400–600 — текст; IBM Plex Mono — eyebrow, мета, чипы, бейджи, футер.
- **Темы**: токены на `:root` (светлая), переопределение под `@media (prefers-color-scheme: dark)` с гардом `:root:not([data-theme="light"])` и дублем в `:root[data-theme="dark"]`.
- **Токены**: `--bg --panel --panel-2 --ink --ink-2 --ink-3 --line --accent --shadow` + 4 семантические пары `--crit/--crit-bg --biz/--biz-bg --imp/--imp-bg --pol/--pol-bg`.
- Светлая палитра: фон `#F4F5F8`, панели белые, чернила `#171B24`, акцент `#3D5AFE`; тёмная: фон `#0E1017`, панели `#171A22`.
- Контейнер `max-width:1080px`, карточки: радиус 14–16px, `border:1px solid var(--line)`, мягкая двойная тень.
- H1 — `clamp(28px, 5vw, 44px)`, `letter-spacing:-.02em`; лид ограничен `max-width:66ch`.
- Никакого JS — чистая статика.

## Скелет разметки

```html
<title>{Проект} · Что дальше</title>
<link rel="stylesheet" href="…Archivo…IBM+Plex+Sans…IBM+Plex+Mono…">
<style>/* токены + компоненты, см. выше */</style>
<div class="wrap">
  <header class="head">
    <div class="eyebrow">{контекст · этап}</div>
    <h1>{Проект}: {вопрос документа по-человечески}</h1>
    <p>{откуда данные} … <b>что чиню я</b> и <b>что решаешь ты</b> … {принцип порядка}.</p>
    <div class="meta"><span>{дата}</span><span class="mono">{N находок → M блоков}</span><span class="mono">{что после}</span></div>
  </header>

  <div class="verdict">
    <h2>Главное одной фразой</h2>
    <p>{самая опасная дыра, 3–4 предложения, жирным ключевое} … начинать надо отсюда.</p>
  </div>

  <section class="phase"><!-- критичный -->
    <div class="phase-head"><span class="tag crit">Блок 1</span><h2>{заголовок-принцип}</h2></div>
    <p class="phase-sub">{что означает блок + владелец}</p>
    <div class="grid">
      <div class="card">
        <div class="card-top"><span class="chip code">Код</span><h3>{суть}</h3><span class="eff">M</span></div>
        <p><b>Что:</b> {механика}.</p>
        <p class="why"><b>Зачем:</b> {последствия без этого}.</p>
      </div>
    </div>
  </section>

  <section class="phase"><!-- решения: tag biz, chip biz, лейбл «Что решить:», eff «—» -->…</section>
  <section class="phase"><!-- скоро: tag imp, карточки одним абзацем без лейблов -->…</section>

  <div class="foot">{отложенное с числом и примерами} + {рекомендация порядка одним предложением}.</div>
</div>
```

## Чем наполнять (процесс)

Содержимое берётся из свежей ревизии проекта (аудит кода/спеки/созвонов) и памяти `.forge/` (status, direction, decisions). Пайплайн: собрать находки → свернуть в 3–4 блока по осям «владелец» × «срочность» → выбрать один главный вывод для вердикта → критичному дать «Что/Зачем», среднему — фразу, остальное — в футер с числом.
