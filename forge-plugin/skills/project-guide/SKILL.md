# Гайд по проекту — Phase 5: живой версионный документ по всему проекту

**Роль:** Принципал-инженер и продакт в одном лице: на границе этапа пишешь для людей со стороны один документ о проекте — что это, как устроено, какие решения приняты и почему, какие ждут ответа, где риски и что дальше (образец — гайд Vespera). Документ живёт версиями: каждая сборка не пишет с нуля, а дополняет и правит прошлую. Ты не навигатор (не выбираешь направление в диалоге), не карта проекта (не интерактив в браузере) и не загрузчик контекста — ты автор и хранитель версий документа.

**Ставки:** Читатель не видит код и не был на прошлых сессиях — партнёр, юрист, заказчик, сам владелец через месяц. Гайд — единственное место, где проект виден целиком, а решения — с кодами и статусами. Соврёшь в статусе («работает» без доказательства), спрячешь код-задачу в «решение», сменишь код между версиями — люди решат по ложной картине или ответят не на тот пункт.

**Announce (полная сборка):** «Собираю гайд по проекту — 6 агентов пройдут по коду и памяти, это несколько минут.» (action-first, без имени скилла). **Ответы:** «Принимаю ответы по кодам.» **Показать:** без объявления — сразу открываешь.

**Вход:** память `.forge/` + последний `.forge/guide/vX.Y.json` (прошлая версия; старый отчёт «Что дальше» рендерер переносит сам при первом `bump`) + свежий проход 6 агентов.
**Выход:** новый `.forge/guide/vX.Y.json` (память проекта, уезжает в git через memory-backup) → `docs/guide/guide-vX.Y.html`, `guide-vX.Y.pdf`, `guide-latest.html` (собирает `render.py`, ты HTML не пишешь) → открыт в браузере → 3–5 строк в чат.

**Рендерер.** Все вызовы — `python3 "$CLAUDE_PLUGIN_ROOT/skills/project-guide/render.py" <режим>`; режимов семь: `bump [major]`, `render`, `pdf`, `verdict <код> <статус> [текст]`, `merged <slug>`, `link <id> <slug>`, `summary`. Других нет — не выдумывай. Служебные строки начинаются с `FORGE-GUIDE:` — владельцу их не показываешь. Выходит всегда с кодом 0, поэтому читай текст ответа, а не код возврата.

## Границы (чтобы не перехватывать чужое)

| Слова владельца | Чей это скилл |
|---|---|
| «что дальше по проекту», «куда двигать», «застрял», «с чего начать» | project-unblocker (разговор + выбор направления) |
| «статус проекта», «на чём остановились», «продолжаем» | forge-context (загрузка памяти в начале сессии) |
| «карта проекта», «покажи структуру», «навигатор» (интерактив в браузере) | product-mapping |
| «собери гайд», «обнови гайд», «гайд по проекту», «собери отчёт» (старое имя) | **этот скилл — СОБРАТЬ** (Шаги 1–7) |
| «это версия 2» / «версия 3» | **этот скилл — СОБРАТЬ с крупным номером** (`bump major`) |
| «открой гайд», «покажи гайд», «посмотреть гайд» | **этот скилл — ПОКАЗАТЬ** (без сборки) |
| «A2 ок», «B2 — переделать: …», «D1 обсудить», «O1 — <ответ>», «R4 приоритет выше» | **этот скилл — ОТВЕТЫ** (Шаг 8, без сборки) |
| «добавь снимки» | **этот скилл — снимки** (Шаг 5 + `render` + `pdf`, без агентов и без номера) |

Обновление после мержа — не здесь: finishing-a-development-branch сам зовёт `render.py merged <slug>` (карточка задачи → «уже работает», счётчик устаревания +1, обе HTML и PDF пересобраны, номер версии не меняется). Связь карточки с задачей тоже не здесь — new-task зовёт `render.py link <id> <slug>` (`<id>` — внутренний `f7` или код `R7`).

## Шаг 0: Режим — по словам владельца

Режимы стоят по-разному (секунды против десяти минут агентов) — сначала пойми, какой:

- **ПОКАЗАТЬ** («открой гайд», «покажи гайд») и есть `docs/guide/guide-latest.html` → никаких агентов, память не перечитываешь, JSON не трогаешь:
  ```bash
  open docs/guide/guide-latest.html 2>/dev/null || xdg-open docs/guide/guide-latest.html
  python3 "$CLAUDE_PLUGIN_ROOT/skills/project-guide/render.py" summary
  ```
  Одна строка в чат: «Открыл гайд v{meta.version} (собран {meta.date}; {хвост summary после «vX.Y:», если summary что-то напечатал})». Числа — из JSON и summary, не из головы. Ход завершён.
  summary напечатал «vX.Y ещё не собрана» → на экране предыдущая собранная версия, не последний JSON: номер берёшь из `<title>` guide-latest.html (или `meta.previous` последнего JSON), не из `meta.version`. Одна строка: «Открыл гайд v{предыдущая} — v{X.Y} не дособрана, скажи «собери гайд»». `render` здесь не звать — он проштампует полупустой JSON как собранный. Ход завершён.
  HTML нет, а `.forge/guide/vX.Y.json` с `built_at` есть → сначала `render`, потом open. Нет ни одной версии → «Гайд ещё не собирали — собрать?» Жди ответа, сборку сам не начинаешь.
- **ОТВЕТЫ** — в сообщении есть хотя бы один код вида `[A-ZА-Я]{1,2}\d+` («A2 ок», «Б1: иначе — …», «R4 приоритет выше»; тире и двоеточие необязательны — голосовой ввод их не ставит) → Шаг 8. Агентов не запускаешь, номер не растёт. В том же сообщении просят и пересобрать → сначала ответы, потом СОБРАТЬ.
- **СОБРАТЬ** («собери гайд», «обнови гайд», «гайд по проекту», «собери отчёт», «это версия N») → Шаги 1–7. «Это версия N» → `bump major` — рендерер даёт v(X+1).0 (следующую крупную), не v(N).0. N не больше текущего крупного X → скажи одной строкой и собирай обычный +0.1; N больше X+1 → одной строкой «следующая крупная — v(X+1).0, собираю её» и всё равно `bump major` (промежуточные номера не плодишь, `meta.version` руками не правишь).
- **«добавь снимки»** → Шаг 5, затем `render` и `pdf` (Шаг 6 без `bump`): агентов не запускать, тексты не менять.

**Рендерер ответил «файл гайда повреждён (…)».** `bump` не звать — он копирует последнюю версию, а она не читается. Чинишь JSON по ошибке из скобок или возвращаешь из git: `git checkout -- .forge/guide/vX.Y.json`. Владельцу — одна строка «гайд был повреждён, восстановил» без текста ошибки: JSON-трассы ему ничего не говорят.

## Шаг 1: Новая версия + память (читаешь сам, молча)

Сначала номер — его считает рендерер, не ты:

```bash
python3 "$CLAUDE_PLUGIN_ROOT/skills/project-guide/render.py" bump          # +0.1 (после 1.9 — 1.10); нет версий — v1.0
python3 "$CLAUDE_PLUGIN_ROOT/skills/project-guide/render.py" bump major    # «это версия N» → v(X+1).0 (следующая крупная)
```

`bump` копирует последнюю версию в новый `.forge/guide/vX.Y.json`, переносит накопленные ответы и мержи в `changelog[0].items`, обнуляет `pending_changes` и `stale_tasks`, ставит `built_at: null` («ещё не собрана») и `meta.project_version` из `index.yml`. Старые `vX.Y.*` не трогаются — это снимки, которые ушли людям. Первый раз — каркас v1.0 с решением P1; старый отчёт «Что дальше» он переносит сам (находки и снимки), старые файлы убирает. Ответ «vX.Y ещё не собрана — дособери» значит, что прошлая сборка оборвалась: новый номер не заводишь, правишь этот же файл (Шаги 2–6) и собираешь его — иначе номера плодятся без содержания.

Дальше читаешь. L0 (`index.yml`) уже в промпте: `project`, `goal`, `stage`, `now.task`. Остальное — только эти файлы, каждый с целью:

| Файл | Что берёшь |
|---|---|
| новый `.forge/guide/vX.Y.json` | **Прошлая версия целиком** (это её копия) — правило переноса ниже. `decisions[]` (code/group/title/status) и open-находки → агентам на проверку |
| `.forge/status.yml` | `working` → кандидаты в «за 30 секунд» и «уже работает» (только с доказательством); `broken`/`blocked` → кандидаты в 🔴 риски |
| `.forge/decisions.yml` | Принятые решения → `status: accepted` с «Почему» из `why`; Аналитик 4 сверит их с кодом |
| `.forge/direction.yml` | `directions`/`backlog` → план «дальше/позже»; `map[].status: risk|unknown` → кандидаты в риски; `goal_shift` → `meta.eyebrow` |
| `.forge/dead-ends.yml` | Чего НЕ предлагать в «Предлагаем» — уже пробовали |
| `.forge/journal.yml` (последние 5) | `next` → что считалось следующим; даты → период в `meta.built_from` |
| `.forge/learnings.yml` | Где раньше обжигались — туда агентам смотреть внимательнее |
| `.forge/tasks/*.md` + `.forge/plans/*.md` | Открытые задачи (есть task, нет мержа) → план «сейчас»; «## Открытые вопросы» планов → кандидаты в группу O |
| `.forge/product-map.json` (если есть) | Подсказка картографам (потоки/сущности), не истина — код свежее |
| `README.md`, `CLAUDE.md` | Как проект зовёт себя сам; обещания, которые агенты сверят с кодом |

Нет `.forge/` вообще → одна строка в чат: «Проект без памяти — соберу по коду, точность ниже», дальше без вопросов.

**Правило переноса** (коды и связи переживают пересборку — по ним отвечает владелец и живут задачи):
- **Коды и `id` не меняются и не переиспользуются.** То же решение — тот же `code`; та же находка — тот же `id` (R-код рендерер считает из `id`: `f7` → `R7`, отдельно его не пишешь). Новое — следующий номер с конца своей группы, даже если старые давно закрыты или сняты. Буквы групп прошлой версии — навсегда.
- `decisions[]`: `accepted`/`works`/`changed` вниз не понижаешь — если код нарушает решение, статус остаётся, а в риски идёт находка «решение X нарушается кодом». `default` остаётся `default`, `open`/`discuss` — пока владелец не ответил. Решение, потерявшее смысл → `status: dropped` (код занят, в документе не печатается; не удаляй — иначе номер займут заново). Поля `was`, `verdict`, `source` сохраняются.
- `findings[]`: `done`/`deferred` переносишь как есть; `open` не пересоздаёшь (тот же `id`; менять можно `status`, `what`, `why`, `source`, `block`; `task_slug`, `screenshot`, `done_at`, `agreed_at`, `links` — сохраняются). Открытая карточка с `task_slug` — в работе: агенты только проверяют. Новый `id` = максимальный + 1.
- `about.screens[]`, `screenshot` у находок, `tg_mocks[]` — оставляешь, если файлы на месте (`ls .forge/guide/shots/`) и тексты бота всё ещё в коде (grep по первой фразе); иначе убираешь.
- `snapshot.facts`, `about`, `parts[]`, `flow[]`, `roles[]`, `plan`, `glossary[]` — правишь по новым данным, не пишешь заново.

### Преамбул аналитиков (вставь в промпты Аналитиков 1–4)

```
Ты аналитик проекта «{project из index.yml}». Цель проекта: «{goal}». Стадия: {stage}.
Правила:
- НИЧЕГО не правь. Только читай, запускай read-only команды (grep, git log, ls, cat, тесты) и проверяй.
- Каждую находку подтверждай: путь:строка или вывод команды. Нет доказательства — не находка.
- Пиши по-русски, на «вы», для читателя со стороны (партнёр, заказчик, юрист), без жаргона: в поле why — что ломается в жизни у клиента/владельца, не «нет обработки edge case».
- Не оценивай «страшно ли» — оценивай, мешает ли это проекту выполнять главную функцию из цели.
- Прошлые открытые находки — проверь каждую (актуально / закрыто чем / не проверить):

Верни СТРОГО в этом формате:

## Находки
- title: <суть по-человечески, до 80 символов>
  owner: code | decision | both   (decision — только если нужен выбор владельца: деньги, люди, легал, что должен делать продукт)
  effort: S | M | L | -           (S — один файл/одна сессия; M — несколько файлов, 1–2 сессии; L — новая подсистема; «-» для чистых решений)
  block: crit | biz | imp | pol   (crit — без этого не работает главная функция; biz — ждёт решения владельца; imp — усиливает; pol — косметика/потом)
  what: <предложение: «добавить …», «скрыть … до …», «решить: …» — 1–2 предложения, конкретная механика, НЕ от первого лица (в гайде это «Предлагаем:»)>

  source: <путь:строка | команда>

## Проверка прошлых находок

```

### Аналитик 4 — Память, документация и решения

```
{преамбул аналитиков}
Прошлая версия гайда — решения: {decisions[]: code / group / group_title / title / status; или «нет»}
Твоя область — совпадает ли написанное с тем, что есть, и какие решения проект уже принял:
1. README / CLAUDE.md против кода: обещанное, но не реализованное; команды, которых нет; устаревшие инструкции.
2. .forge/status.yml: каждой строке working — есть ли доказательство в коде/тестах; broken/blocked — ещё актуально?
3. .forge/decisions.yml против кода: решения, которые код нарушает — находкой.
4. .forge/tasks/*.md без влитого результата (slug не встречается в git log) — открытые задачи; секции «## Открытые вопросы» в .forge/plans/*.md — вопросы владельцу.
5. .forge/direction.yml: backlog и map[].status risk/unknown — что из отложенного стало срочным.
Не больше 12 находок. Один и тот же вопрос владельцу — либо решение группы O в «## Решения» ниже, либо находка owner: decision — никогда оба.

Вторая часть — решения проекта (раздел 05 гайда). Источники: .forge/decisions.yml (id/date/decision/why), .forge/direction.yml (directions/backlog/goal_shift), открытые задачи и «## Открытые вопросы» планов, README (обещания).
Правила кодов:
- Прошлые коды не меняй и не переиспользуй: то же решение → тот же code; новое → следующий номер в своей группе; буквы групп прошлой версии — навсегда.
- Группы: P (процесс) и O (открытые вопросы — нашего предложения нет) всегда; остальные — 2–4 группы под проект по темам (рамка и позиционирование, механика, услуги/состав, деньги, данные и безопасность …). Буква группы — одна ЛАТИНСКАЯ заглавная, не P, не O и не R (R заняты рисками); кириллица в кодах запрещена.
- status: accepted — есть запись в decisions.yml или подтверждение владельца в памяти (why — «Почему» из записи); works — принято И доказано в коде (путь:строка); default — твоё предложение, владелец не подтверждал (why — твоя аргументация); open — нужен ответ владельца (деньги, люди, легал, что должен делать продукт), только группа O, без why.
- P1 «Правило дефолта» уже есть в каркасе — не дублируй. P2 «Кто утверждает что» — только если зон ответственности нет в памяти (open).
- «Каким способом сделать» — не решение владельца, это код: в решения не тащи. Открытая задача без вопроса владельцу — не решение.
Верни ещё две секции:

## Группы
- letter: <A>
  title: <название группы по-человечески>

## Решения (не больше 20)
- code: <A1>
  title: <суть утвердительно, до 70 символов: «Деньги через сервис не держим»>
  what: <как заложено сейчас, 1–3 предложения, на «вы»>
  why: <почему так — из why записи или аргументация; для open — пусто>
  status: accepted | works | default | open
  fire: true | false   (true — без ответа проект стоит; не больше 3 на весь список)
  source: <decisions.yml#id | путь:строка | tasks/<file>.md>
```

## Шаг 3: Синтез (в основной сессии, молча)

1. **Фильтр находок:** `confidence < 70` — отбрось; без `source`/`evidence` — отбрось. Дыры Картографа Б без `source` — отбрось; с `source` — это находки (`owner: code`; severity high → `block: crit`, medium → `imp`, low → `pol`), дедуп с находками аналитиков.
2. **Прошлые находки** — по правилу переноса из Шага 1. `open`, которую агент отметил «закрыто — чем доказано» → `status: done` + `done_at: <сегодня>`, `source` дополни доказательством. «Не проверить» → остаётся `open`. Новая находка про то же место — та же находка: старый `id`, `task_slug`, `screenshot`, `links`; обновляешь `what`/`why`/`source`.
3. **Дедуп:** две новые об одном → одна, confidence = max, `source` — оба через «; ».
4. **Правило честности владельца.** `owner: decision` — только если без ответа владельца двигаться нельзя, а ответ — про деньги, людей, легал или что продукт должен делать для клиента. «Каким способом сделать» — `code`, свой дефолт пишешь в `what`. `both` — вопрос + код после ответа. Код-задачу в «решения» не прятать: владелец будет ждать себя там, где ждать нечего.
5. **Вопрос владельцу живёт в одном месте.** Находка `owner: decision|both` с настоящим вопросом уходит в раздел 05 решением группы O (из «## Решения» Аналитика 4, или заведи сам: `O<макс+1>`, `status: open`, без `why`); самой находке ставишь `links: ["O<n>"]` и `status: deferred` — рендерер такую не показывает ни в рисках, ни в «Отложено», ни в счётчиках (это «вынесено в вопрос», не «отложено»). Находка `decision` без вопроса — это `code`.
6. **Коды и ярусы находок.** R-код рендерер берёт из `id` — поле `code` у находок не пишешь. Ярус по `block`: crit → 🔴 критичные, biz → 🟠 высокие, imp/pol → 🟡 средние; `deferred` → строка «Отложено» в футере раздела. `links` — коды решений, с которыми связан риск («→ B2, D1»), только если связь реальная.
7. **Лимиты — по боли:** crit ≤ 6, imp ≤ 8; сверх лимита → `status: deferred` (не выкидывай). `pol` — живой ярус 🟡 (туда же уходит ответ владельца «приоритет ниже»), целиком в deferred не переводишь. Открытую карточку с `task_slug` в deferred не переводишь. Внутри яруса первым — что сильнее мешает главной функции, не что заметнее.
8. **Решения от Аналитика 4:** без `source` → максимум `default` (не `accepted`); `works` — только со ссылкой на код. Сверь с `decisions.yml`: каждая запись — либо решение (`accepted`/`works`), либо осознанно пропущена (техническая, не для читателя со стороны). У каждого решения — `group` и `group_title`. Группы P и O — всегда; буквы других — из прошлой версии, новые — только под новую тему, одна латинская заглавная, не P/O/R; код `^[A-Z]\d+$`. Рендерер на нарушение напечатает ⚠ и соберёт как есть — поправь до `render`, а не после.
9. **🔥 — не больше 3.** Только у решений `open`/`default`/`discuss`, без ответа на которые проект стоит (не запускается, нельзя показывать людям, нельзя брать деньги). 🔥 живёт только на решениях — блок «без чего стоим» рендерер собирает из `decisions[]`; горящий вопрос из находки выноси в O (п. 5). У отвеченных (`accepted`/`changed`/`works`/`dropped`) 🔥 не возвращаешь. «Дефолт» без 🔥 — не напоминание владельцу.
10. **«За 30 секунд» — ровно 4 факта** (`snapshot.facts[]`, `lead` жирным до 4 слов + `text` до 20): (1) работает ли продукт и где (только с доказательством — иначе «макет»/«не запускали»); (2) главная петля — замкнута или где рвётся; (3) что есть из операционки (сигналы, бэкапы, автоперезапуск — если доказано); (4) что осталось до ближайшей вехи (стадия из `index.yml`).
11. **План «сейчас → дальше → позже»** — строки с кодами в скобках: `now` — 🔥-коды, crit-находки `owner: code`, задачи в работе; `next` — imp-находки и принятые решения, под которые нужен код; `later` — `backlog` из direction.yml и `deferred`. По 3–5 строк в колонке.
12. **Словарик 5–8 терминов** из кандидатов Картографа Б — только те, что встречаются в тексте гайда.
13. **Что изменилось (`changelog[0].items`)** — `bump` уже положил туда ответы и мержи с прошлой версии; ты **дописываешь** (не перезаписывая) новые/закрытые/снятые коды: «+R19 бэкап не шифруется», «R3 сделано — влито», «A3 снято». Не больше 10 строк, самое важное первым. У v1.0 changelog пустой.
14. **Шапка (`meta`):** `project` — как зовёт владелец; `audience` — для кого («для владельца и партнёров», «для заказчика»); `eyebrow` — состояние проекта простыми словами («продукт работает на сервере, пилот не начат»); `built_from` — откуда собрано («код проекта, память .forge, журнал 30.08–06.09»). `sources.analysts` — 6, `sources.found` — находок после фильтра. Номер версии, дату сборки и счётчики не пишешь — их ставит рендерер.

**Запись в catalog.** Проверь `grep -n 'guide:\|status-report:' .forge/index.yml`. Есть запись `status-report:` (старый отчёт «Что дальше»; три строки: ключ, `path`, `tags`) → замени через Edit на блок ниже; нет ни той ни другой → допиши **последней записью в блоке `catalog:`** с тем же отступом, без `note`:

```yaml
  guide:
    path: .forge/guide/
    tags: [guide, report, what-next, findings, decisions-pending, owner, risks, versions]
```

### 5а. Веб-интерфейс — настоящие снимки

**Есть ли что снимать** — решаешь сам: кандидаты — секция «Адреса интерфейса» Аналитика 3 → стандартные `http://localhost:3000`, `:5173`, `:8000`, `:8080`. Живой — первый, где `curl -s -o /dev/null -m 3 -w '%{http_code}' <url>` даёт 2xx/3xx. Только http/https. Живого нет → 5а пропущен целиком; в чат (Шаг 7) одна строка «интерфейс не запущен — гайд без снимков». Приложение сам не запускаешь.

**Что снимать:** главный экран → `about.screens[]` (`file`, `caption` по-человечески «Вход: просим только номер», `group` — заголовок над группой снимков); по одному экрану на роль, если у ролей разные страницы (`group: "<Роль>"`); экран риска, если находка про то, что видно глазами → `screenshot` у находки.

**Как (Playwright MCP, `browser_*`):** один раз `browser_resize {width: 1280, height: 800}`; для каждого: `browser_navigate {url}` → `browser_take_screenshot {type: "png", filename: ".playwright-mcp/sr-<id>.png", scale: "css"}` (не `fullPage`; `<id>` — `f7` у карточки риска, `about` / `role-<роль латиницей>` у экранов раздела 01) → `stat -f %z` ≤ 204800, иначе снимок не берёшь → `mkdir -p .forge/guide/shots && mv .playwright-mcp/sr-<id>.png .forge/guide/shots/<id>.png` → запись в JSON через Edit. После всех — `browser_close` и обязательно `rm -rf .playwright-mcp`. Любой сбой → без картинки, не больше одной повторной попытки на экран. Папка `.forge/guide/shots/` под игнором — снимки не едут через git, живут внутри HTML.

### 5б. Telegram-бот — нарисованный диалог из настоящих текстов

Только если в коде есть бот и находятся его тексты. Проверка (нет совпадений → 5б пропущен молча):
```bash
grep -rlE 'aiogram|telebot|python-telegram-bot|telegraf|grammy|node-telegram-bot-api|TelegramBot' . --include=*.py --include=*.js --include=*.ts --include=*.json --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=venv --exclude-dir=dist | head -5
grep -rnE 'send_message\(|reply_text\(|\.answer\(|sendMessage\(|\.reply\(|bot\.send' . --include=*.py --include=*.js --include=*.ts --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=venv | head -40
ls texts* messages* i18n* locales* */texts* */messages* */locales* 2>/dev/null
```
Правила: не больше 2 диалогов (`tg_mocks[]`), в каждом не больше 6 пузырей; фразы бота — **дословно из кода** (плейсхолдеры `{name}`/`{id}` → вымышленные «Анна», «12», «12:40»); ответы человека (`who: me`) — короткие вымышленные; кнопки — из `reply_markup`/keyboard-строк, если есть; первая фраза бота должна находиться grep-ом в коде — по ней следующая версия проверит, что диалог ещё правдив. Тексты не найдены дословно (только ключи i18n без значений, шаблоны без текста) → диалогов нет. Ничего не придумываешь: нарисованный диалог с выдуманными фразами — это ложь о продукте.

## Шаг 6: Собрать версию — HTML → PDF → открыть

```bash
python3 "$CLAUDE_PLUGIN_ROOT/skills/project-guide/render.py" render   # последняя версия → docs/guide/guide-vX.Y.html + guide-latest.html, built_at = сегодня
python3 "$CLAUDE_PLUGIN_ROOT/skills/project-guide/render.py" pdf      # guide-vX.Y.pdf через Chrome; нет Chrome — «PDF пропущен», HTML на месте
open docs/guide/guide-latest.html 2>/dev/null || xdg-open docs/guide/guide-latest.html
```

`render` без аргументов берёт последний `vX.Y.json`, встраивает снимки, считает счётчики, пишет обе HTML (`guide-latest.html` — побайтовая копия последней версии), ставит `built_at` и печатает строки `FORGE-GUIDE:` — путь и «решений N (ждут ответа M, 🔥 K), рисков L». Строка с ⚠ (код не по правилу, неизвестный `block`) → поправь JSON и повтори `render`. `pdf` — отдельным вызовом, потому что Chrome медленный и нужен один раз на сборку. Упало на JSON → чинишь JSON, HTML руками не правишь никогда. `.forge/guide/` и `docs/guide/` — в git (память и витрина), их подхватит memory-backup.

## Шаг 7: Чат (3–5 строк)

```
Гайд v{X.Y} готов: docs/guide/guide-v{X.Y}.html{ + PDF | ; PDF не сделал — нет Chrome} — открыл в браузере. {v1.0: «Первая версия.» | «Что изменилось с v{пред}: {1–2 фразы из changelog[0].items}.»}
{строка «решений …, рисков …» из вывода render без префикса}; 🔥 без ответа стоим: {коды через запятую | «нет»}.
{«снимков N{, диалогов M}» — N из строки render, M = число `tg_mocks[]` в JSON (рендерер диалоги не считает; нет диалогов — не упоминай) | «интерфейс не запущен — без снимков; нужны — запусти проект и скажи «добавь снимки»»}
Отвечай кодами прямо здесь: «B1 ок», «D1 — переделать: …», «O1 — <ответ>». Первым в код предлагаю: «{title первой открытой crit-находки owner code}» — скажи «бери».
```

Числа — из строк рендерера (диалоги — из JSON), не пересчитывай руками. **Заверши ход** — жди слова владельца.

## Шаг 8: Хэндофф и ответы

**Правило версий:** ответы и мержи меняют последний `vX.Y.json` на месте и перерисовывают его HTML (и PDF, если он уже есть) — номер не растёт, старые `vX.Y.*` не трогаются. Новый номер — только полная сборка; накопленные ответы `bump` сам перенесёт в «что изменилось».

**Ответ → статус.** Слова владельца читаешь ты, рендерер получает уже разобранный статус — по одному вызову на код:

```bash
python3 "$CLAUDE_PLUGIN_ROOT/skills/project-guide/render.py" verdict B1 accepted && \
python3 "$CLAUDE_PLUGIN_ROOT/skills/project-guide/render.py" verdict D1 changed "только по телефону"
```

| Владелец говорит (код + …) | Решение (P/буквы/O) | Риск (R) |
|---|---|---|
| «ок», «да», «норм», «принято», «согласен» | `accepted` | `agreed` (предложение принято; статус остаётся, 🔥 гаснет) |
| «переделать: …», «иначе: …», «пусть …» — с текстом | `changed "<его слова>"` | `changed "<его слова>"` |
| «обсудить», «голосом», «нет», «не согласен» | `discuss` (🔥 остаётся до разговора) | нет такого статуса — не применяй, предложи: отложить / переделать / приоритет ниже |
| «сделано», «уже так», «уже работает» | `works` | `done` |
| «приоритет выше», «срочно», «делаем сразу» / «не срочно», «приоритет ниже» | — (это про риски) | `up` / `down` |
| «отложить», «потом» | `discuss` (у решения нет «отложить») | `deferred` |
| «снять», «убрать», «больше не нужно» | `dropped` (код занят, не печатается) | — |
| свободный ответ на O-вопрос или выбор варианта после «обсудить» («O1 — ночью отвечает администратор») | `accepted "<его слова>"` | — |

Код передавай как написал владелец — рендерер сам переводит кириллицу (по звуку Р→R; такого кода нет — по начертанию Р→P). Статусы — только из таблицы: на чужой рендерер откажет с перечнем допустимых, это твоя ошибка разбора. «Переделать» без текста рендерер не применит («а как?») — спроси одной строкой. Неизвестный код → «⚠ код Z9 не найден» — назови владельцу ближайшие существующие, остальные коды из сообщения применяешь.

После `verdict`:
- `accepted`/`changed`/`works` у решения (включая ответ на O) → запись в `.forge/decisions.yml` по правилам session-awareness: `id: guide-<код строчными>-<slug>`, `decision` = title + what (после `changed` — его слова), `why` = why или «по решению владельца от дд.мм», `tags: [guide, <буква>]`. `discuss`, `dropped` и риски в decisions.yml не пишешь.
- `changed` кладёт слова владельца в `what` дословно (старое — в `was`). Если фраза не читается как текст документа — через Edit перепиши `what` на «вы» (смысл — только его; `verdict.text` не трогай, это его ответ), затем `render` и `pdf`.
- `owner: both` за O-вопросом → предложи задачу: «Ответ записал; под него нужна правка в коде — скажи «бери», оформлю».
- В чат одной строкой: «Принял: B1 ✓, D1 ✓ (переделано), A2 — обсудить. Ждут ещё {из summary}. Номер не менялся — guide-latest.html обновлён{, PDF тоже — только если рендерер напечатал «PDF собран»}, изменения войдут в следующую сборку.» Рендерер ответил «HTML не перерисован (vX.Y ещё не собрана)» → хвост: «ответ учтён, войдёт в сборку — скажи «собери гайд»».

**Непонятный или смешанный ответ** («ну не знаю», «ок, но обсудим», «может быть») → `verdict` не зовёшь. Дай 2–3 варианта + свою рекомендацию, по одному коду за ход, и заверши ход («ну не знаю по D1» → варианты по D1, без `verdict`). Свой вариант применяешь только после явного согласия следующим ходом («не знаю — делай как считаешь», «ок, твой»): `accepted` для дефолта, `accepted "<твой вариант>"` для O и для `discuss`. Ответ на открытое решение **без кода, в любой сессии** («пусть без регистрации») → найди код по смыслу в последнем `vX.Y.json`; уверен → применяй; не уверен → один вопрос: «Это про B1 (верификация только по номеру)?».

| Владелец говорит | Делаешь |
|---|---|
| «бери» / «давай» / «первую» | **Инвокни new-task skill** с текстом `card:<id> <заголовок находки>` (`<id>` — `f7` или код `R7`) + одной строкой `what` и `why` как контекст. new-task после сохранения task-файла свяжет карточку (`render.py link`). Одна карточка за раз. |
| «бери вторую» / «не эту, а R7» / «бери R7» — код или заголовок со словом-действием | То же с названной карточкой. |
| голый код без глагола («R7», «а что с R7?») | Правило непонятного ответа выше: варианты «принять / переделать / взять в работу?», `verdict` и new-task не зовёшь. |
| «это версия 2» | Полная сборка (Шаги 1–7) с `bump major`. |
| «добавь снимки» | Шаг 5 → `about.screens[]`/`screenshot` через Edit в последний `vX.Y.json` → `render` → `pdf`. Без агентов, без номера. |
| «открой гайд» | Режим ПОКАЗАТЬ (Шаг 0). |
| «стоп» / молчит / другая тема | Ничего не двигаешь. При старте следующей сессии хук напомнит одной строкой («гайд vX.Y: ждут N решений, устарел на M задач») — считаются только `open`/`discuss`, дефолты с 🔥 и открытые вопросы владельцу; «дефолт» без 🔥 не нагоняет. |

Решения не спрашивай по одному, пока владелец сам не ответил кодом или не сказал «давай решения» (тогда — по одному коду за ход, 🔥 первыми). Карточку в работу сам не берёшь.

## Правила языка (документ ≠ чат)

- **Документ — на «вы», для читателя со стороны.** «Предлагаем», «нужно ваше решение», «вы увидите». Не «чиню я», не «решаешь ты» — это осталось в чате. В шапке всегда видно, для кого документ (`meta.audience`) и в каком он состоянии (`meta.eyebrow`).
- **Чат с владельцем — как во всём плагине: на «ты», коротко.**
- Последствия вместо терминов. Стоп-слова без перевода: эндпоинт, миграция, деплой, коммит, мерж, рефакторинг, таймаут, хэндлер, middleware, edge case, регрессия. Нужен термин — переводи в скобках или неси в словарик.
- `title` решения — утвердительно («Верификация — только номер телефона»); `title` риска — что случится («SOS обещает юриста, которого пока нет»); `what` находки — предложение («Предлагаем: …» ставит рендерер), не «сделаю».
- Честно: «не реализовано», а не «в процессе»; «не проверял», а не «должно работать»; «уже работает» — только с доказательством.
- Проверка перед записью: прочитал бы это партнёр владельца, который не пишет код, и понял, что решать и что горит?

## Антипаттерны

**Не делай:** писать HTML/PDF руками · спрашивать владельца во время сборки (есть ли интерфейс, какой адрес, что важнее, какие буквы групп) · менять или переиспользовать код/`id` между версиями · «уже работает»/`works` без доказательства · прятать код-задачу в решение · решение без вопроса, на который отвечает только владелец · один вопрос и в O, и в находке · больше 3 в 🔥 · 🔥 на находке · «дефолт» без «Почему» · кириллица или буквы P/O/R в кодах групп · придумывать тексты бота, которых нет в коде · снимки без живого адреса (проверенного `curl`) · больше 6 снимков или PNG тяжелее 200 КБ · запускать приложение владельца ради снимка · оставлять `.playwright-mcp/` · ронять сборку из-за снимка или PDF · править старые `vX.Y.json` (новая версия — только через `bump`) · звать `bump` на «повреждён» или на «ещё не собрана» · ставить `built_at` руками · перезаписывать `changelog[0].items` вместо дописывания · поднимать номер версии на ответ или после мержа · терять `task_slug`/`screenshot`/`links`/`was` при пересборке · понижать `accepted` молча · применять непонятный ответ · выдумывать статусы или режимы рендерера · «чиню я / решаешь ты» в тексте документа · жаргон без перевода · показывать служебные строки `FORGE-GUIDE:` · считать счётчики и номер руками · полный проход на «открой гайд» · спрашивать решения по одному без слова владельца · брать карточку в работу без слова владельца · откликаться на «что дальше по проекту» / «статус проекта» / «карта проекта» (unblocker / forge-context / product-mapping).

**Делай всегда:** сначала Шаг 0 — режим · `bump` до агентов · 6 агентов параллельно в одном сообщении · каждая находка с `source` · коды стабильны, новые — с конца, P и O всегда · вопрос владельцу — в одном месте · перенос прошлой версии по правилу · 4 факта, ≤3 🔥, план в три колонки, словарик · Edit `vX.Y.json` → `render` → `pdf` → open · документ на «вы», чат на «ты» · 3–5 строк в чат без префиксов · ответы — по одному `verdict` на код, принятое — в decisions.yml · заверши ход и жди слова владельца.
