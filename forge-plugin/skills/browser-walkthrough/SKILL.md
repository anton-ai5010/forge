# Прокликай в браузере

Claude проходит веб-страницу как пользователь: открывает, нажимает, заполняет по пути из критерия готовности. Сломанное чинит и проходит заново. Владельцу — строка итога и одна страничка с 3–5 снимками.

**Только по слову владельца.** Ни проверка шагов, ни финал execute этот навык сами не зовут — execute лишь подсказывает строкой «скажи „прокликай“». Браузеры — по правилу «Браузер — один Chrome на всё» из `~/.claude/CLAUDE.md` (DEC-27).

## 1. Путь

- Задача: `task:` из `.forge/state.yml` или slug из ветки `feat/<slug>` / `fix/<slug>-walkthrough` → `.forge/tasks/*-<slug>.md`, раздел `## Критерий готовности`.
- Превращаешь его в 3–8 шагов «действие → что должно быть видно» («нажать „Отправить“ → появилось „Заказ принят“»). Задачи нет — путь из слов владельца. Нет ни критерия, ни слов (сказал только «прокликай») — один вопрос: «Что открыть и что там нажать?»; адрес — из команды запуска, иначе спроси, сам не угадывай.
- Пункты критерия без страницы (настройки, скрипты, тексты в коде) — не проходишь, называешь в итоге «через браузер это не проверить: <что>».
- В чат одной строкой: «иду по странице: N шагов, пара минут».

## 2. Где

- **Своё** — `localhost` / `127.0.0.1`, свой HTML, dev-сервер проекта → помощник в невидимом Playwright (раздел 5).
- **Живой сайт** — домен в интернете → основной чат в Chrome владельца (раздел 6).

## 3. Опасное — везде

Оплата / покупка, отправка от имени владельца или наружу (письмо, сообщение, отзыв, заказ), удаление, загрузка файла с компьютера: всё заполни, а **перед последним кликом** — в чат «Стоп: <что> на <адрес>? да/нет». И на localhost тоже: местная программа может работать с настоящими данными и ключами — адрес правило не отменяет.

## 4. Запуск своего

Адрес не отвечает (`curl -s -o /dev/null -w '%{http_code}' <адрес>`):
- скилл запуска в проекте (`.claude/skills/*/SKILL.md` с описанием запуска) — возьми из него **только команду запуска сервера**;
- нет — скрипт `dev` / `start` из `package.json` (или аналог стека);
- свой HTML — `python3 -m http.server <порт> --bind 127.0.0.1` из папки страницы (Playwright не открывает `file://`).

Порт — всегда свободный, не «обычный» (другой чат может держать тот же и отдать чужую страницу): `python3 -c 'import socket;s=socket.socket();s.bind(("127.0.0.1",0));print(s.getsockname()[1])'`. Сервер — фоном (`run_in_background`), дождись ответа адреса. Команды — с абсолютными путями, без `cd … &&` (такие склейки требуют лишнего разрешения). Встроенный Skill `run` **не вызывай** — он открывает свой браузер. После прохода останови то, что поднял сам.

## 5. Своё — помощник

**Своё — помощник** (модель — по `$CLAUDE_PLUGIN_ROOT/docs/model-roles.md`): Agent `subagent_type: "general-purpose"`, `model: "sonnet"`. Промпт:

```
Пройди страницу как пользователь. Адрес: <адрес>. Шаги: <шаги «действие → что видно»>.
- Только инструменты Playwright (mcp__plugin_playwright_playwright__* или mcp__playwright__*). Недоступны / не отвечают — сразу ответь «заблокировано: Playwright», в Chrome (mcp__claude-in-chrome__*) не ходи.
- На каждом шаге: что видно (browser_snapshot), ошибки консоли (browser_console_messages).
- Оплата / отправка наружу / удаление / загрузка файла — НЕ нажимай, верни «⏸ <что> на <адрес>».
- Вводишь данные — тестовые, с меткой тест-<ЧЧММ>; созданные записи перечисли.
- 3–5 снимков ключевых моментов: browser_take_screenshot, type: "jpeg", filename: ".playwright-mcp/walkthrough-<ЧЧММ>/<N>.jpg" (относительный путь — вне папки проекта Playwright не пишет). Вернул инструмент другой путь — напиши его.
- Код не правь.
Ответ до 25 строк: по строке на шаг «N — ✅/❌/⏸ — что видно — путь снимка»; затем «записи: …» и ошибки консоли.
```

`⏸` → спроси владельца «Стоп: …? да/нет». «Да» — новый помощник **с шага ⏸** (прошлые шаги не повторять; дай ему введённые данные и список созданных записей) и разрешением ровно на это действие. «Нет» — шаг не проверен, в итоге так и скажи.

Ответ помощника проверь до сборки странички: у каждого шага есть строка, файлы снимков существуют. Не хватает — один раз новый помощник на недостающих шагах; снова нет — итог «прошёл частично», без «прошёл».

## 6. Живой сайт — основной чат

Claude in Chrome: `tabs_context_mcp` → своя вкладка `tabs_create_mcp`. Нажимать можно всё, кроме раздела 3. Каждая созданная запись — в список «тестовые записи». Снимки — `computer` `screenshot` с `save_to_disk: true`, путь — тот, что вернул инструмент. Помощникам живой сайт не отдавай: в Chrome они только читают.

## 7. Не смог начать

Отдельный исход: **код не трогай, «прошёл» не пиши**, одна строка владельцу простыми словами:
- не запустилось — одной фразой по-человечески, что не так (текст ошибки — в скобках, если нужен);
- Chrome не подключён — «в Chrome нажми значок Claude и включи»;
- сайт просит войти — «Стою на странице входа <сайт>. Войди сам в этой вкладке и скажи „готово“»;
- Playwright не отвечает — «невидимый браузер не отвечает — проверить своё не могу»; в Chrome владельца вместо него не переходи.

## 8. Сломано → починка

❌ на шаге:
1. Причина — по `systematic-debugging`, без угадывания.
2. На основной ветке (задача уже влита) — перед правкой молча `git checkout -b fix/<slug>-walkthrough`, после прохода предложи «мержим».
3. Правка → в чат «круг N из 3: чиню <что>» → **новый полный проход**.
4. Перед повтором — список созданного прошлым проходом: шаги, создающие записи, — с новыми тестовыми данными; необратимое — снова «Стоп».
5. Не больше 3 кругов. Не вышло — итог «не починил: <что>, причина: <что знаю>», без «готово».

**Живой сайт:** правка в коде на сайт сама не попадает. Причина + правка в коде (если это проект владельца), повтор — только после того, как владелец скажет, что правка выложена на сайт; итог «на сайте пока не починено — правку надо выложить: <что>».

## 9. Страничка

```bash
python3 "<папка этого скилла>/shots-page.py" \
  ~/.claude/forge-logs/<проект>/walkthrough-<ГГГГ-ММ-ДД-ЧЧММ>.html "<итог>" --url=<адрес> \
  [--record="<тестовая запись>" …] "<снимок>::<подпись>" "<снимок>::!починил: <подпись>" …
```

- `<папка этого скилла>` — «Base directory for this skill» из загрузки скилла, абсолютным путём: `$CLAUDE_PLUGIN_ROOT` в Bash бывает пустым. Папку `~/.claude/forge-logs/<проект>/` заранее не создавай — скрипт создаст её сам, закрытой (700).
- Подпись с `!починил: ` — карточка с меткой «было сломано → починил».
- Страница — только владельцу (600): на снимках могут быть его аккаунты. Предупреждение «на телефоне может не открыться» — сними меньше снимков или без `fullPage`.
- Собрал → `open <файл>` (откроется на маке) **и** SendUserFile с этим файлом — так страничка дойдёт и до телефона; в чат — «страничка со снимками — открыл и отправил файлом» + ссылка `[страничка снимков](file://<абсолютный путь>)` для мака.
- «Не смог начать» — страничку не собирай.
- После сборки удали снимки: `.playwright-mcp/walkthrough-<ЧЧММ>/` и сохранённые Chrome.

## 10. Итог в чат

2–4 строки:
- «прошёл в браузере: N шагов — всё работает» / «нашёл и починил: <что>» / «прошёл N из M — шаг K не проверен: <почему>» / «не смог начать: <что>» / «не починил: …»; «всё работает» — только если пройдены все шаги;
- ссылка на страничку;
- тестовые записи (или «не создавал»);
- что через браузер не проверить, если было.
