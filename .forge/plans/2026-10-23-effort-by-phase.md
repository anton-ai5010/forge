# План: глубина размышлений по фазам

**Задача:** см. `.forge/tasks/2026-10-23-effort-by-phase.md` (DEC-22)

**Подход:** сначала замером на пробном скилле выясняем, держится ли `effort: xhigh` из frontmatter дальше первого ответа и не залипает ли на следующие фазы (в записи чата у каждого ответа модели есть поле `perTurnEffort` — по нему и смотрим). Потом убираем из четырёх скиллов просьбу «напиши `/effort high`» (high и так по умолчанию), а execute учим подсказывать глубину из плана, которую впишет критика. `effort: xhigh` ставим плану только если замер показал «держится в фазе и уходит при переходе»; иначе план остаётся на high, честно в отчёте, без обходных механизмов.

**Что увидишь ты:**
- Клод в фазах new-task / refine-idea / plan / critique больше не пишет «напиши `/effort high`».
- План (если замер подтвердит) сам думает глубже — ты ничего не набираешь.
- В конце критики в плане строка «глубина реализации: high» (для денег — xhigh, для прода и удаления данных — max); execute просит переключить только в таких задачах, человеческой фразой, а не «хватит medium».

**Открытые вопросы:** нет.

**Блокеры:** нет.

## Шаг 1: Замер — держится ли effort из frontmatter и уходит ли при переходе `[agent: sonnet]`

Пробный проект в scratchpad (плагин не трогаем), хуки плагина молчат через `FORGE_NESTED=1`.

Файлы пробного проекта:
- `.claude/skills/effort-probe/SKILL.md` — frontmatter `name`, `description`, `effort: xhigh`; тело: «прочитай README.md и notes.txt этого проекта (Read), затем ответь одной строкой "probe ok"» — чтобы внутри хода было несколько ответов модели, как у настоящего плана.
- `.claude/skills/next-probe/SKILL.md` — без `effort`; тело: «прочитай notes.txt, ответь "next ok"» — имитирует переход plan → critique.
- `.claude/commands/effort-cmd.md` — обёртка как у плагина: frontmatter `effort: xhigh` + `disable-model-invocation: true`, тело «Invoke the effort-probe skill and follow it exactly.».
- `README.md`, `notes.txt` — пара строк.

Все ходы сценария — **в одном живом процессе** (`claude -p --input-format stream-json --output-format stream-json`, сообщения подаются по одному; не выходит — интерактивный `claude` в tmux через `send-keys`). Не `--resume`: новый процесс на каждый ход может вести себя иначе, чем чат в VS Code.

Сценарии, 4 хода каждый:
0. **Контроль:** «ответь "ход 1"» × 3, затем «вызови скилл next-probe» — база для сравнения.
1. Ход 1 — `/effort-probe`; ход 2 — «прочитай notes.txt, ответь "ход 2"»; ход 3 — то же «ход 3»; ход 4 — «вызови скилл next-probe».
2. Как 1, но ход 1 — `/effort-cmd`.
3. Как 1, но ход 1 — «вызови скилл effort-probe» (модель зовёт сама — так идёт auto-handoff refine-idea → plan; **решающий сценарий**).

По каждому ответу модели — `perTurnEffort`, `effort`, `entrypoint` из `~/.claude/projects/<проект>/<session>.jsonl`.

**Как проверим:** таблица «сценарий × ход (× ответ внутри хода) → perTurnEffort» в `.forge/notes/effort-by-phase.md` и вывод одним из исходов:
- **держится в фазе, уходит при переходе** — xhigh на ходах 1–3, high на ходе 4;
- **только первый ход** — xhigh лишь на ходе 1;
- **залипает на весь чат** — xhigh и на ходе 4;
- **не работает** — везде как в контроле.
