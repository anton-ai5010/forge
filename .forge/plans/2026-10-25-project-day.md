# План: Директор проекта и отделы — минимум для пробного дня

**Задача:** см. `.forge/tasks/2026-10-25-project-day.md`

**Подход:** Строим на встроенном в Claude Code (копии проекта `.claude/worktrees/`, `EnterWorktree`, `claude agents --json`) и на том, что в плагине уже есть (фазы пишут `.forge/state.yml`, журнал фрагментами, finishing вливает с тестами). Добавляем два скилла — **директор** (видит проект, раздаёт, следит, код не трогает) и **отдел** (обычный чат в своей копии проекта, те же фазы, вопросы пачкой, вливает сам под замком) — и три маленьких скрипта: доска, замок вливания, складывание памяти из inbox. Правила «реализация без ритуала» и «вопросы пачкой в отделе» — правки текстов существующих скиллов. Всё остальное (браузерная доска, тестовые данные для integration) — после пробного дня.

**Что увидишь ты:**
- Слово «директор» (или `/forge:director`) в любом проекте с `.forge/` → один список: **твои дела** (решения, невлитые ветки, письма людям) и **работа Claude по отделам**, у каждого отдела — строка `/forge:department <отдел>` для нового чата, плюс замечания директора вроде «main отстаёт на 454 коммита от feat/cleanup — влить десять секунд». Директор сам код не пишет и задачи не ведёт — только смотрит, раздаёт, замечает.
- Слово «доска» в чате директора → таблица: отдел · задача · фаза · «работает» / «ждёт тебя: <о чём>» / «чат закрыт». Данные берутся из живых чатов и их файлов состояния — директор ничего не пересказывает.
- Вставил строку отдела в новый чат → чат сам уходит в свою копию проекта, ставит свои задачи, **независимые вопросы задаёт одной пронумерованной пачкой** (зависимые — после ответов, не больше двух кругов), дальше обычные фазы с теми же проверками. «Мержим» — вливает сам: замок → свежий main к себе → тесты → память → main.
- Реализация **перестаёт спрашивать «Окей, продолжать?» там, где нечего решать**: чекпоинт-показ показывает результат и идёт дальше («стоп» в любой момент), чекпоинт-решение — ждёт тебя. Решение ты увидишь в самом плане: у каждого чекпоинта строка «Решение владельца: … / нет — показ без остановки». Это правило — для всех задач, не только для отделов.
- Записи памяти по задаче в отделе копятся в `.forge/inbox/<задача>/` и попадают в общие файлы при вливании — ты этого не заметишь, кроме того, что слияния перестанут драться за `decisions.yml`.
- Решения, которые ты, вероятно, захочешь поправить: имя «директор» (вместо «диспетчер»); копия отдела **не удаляется** после дня — только по твоему «убери копию»; чекпоинт-показ идёт дальше без ожидания.

**Открытые вопросы:** нет (имя «директор» — твоё слово, беру).

**Блокеры:** нет.

**Рассмотрели и отвергли:** сторонние доски (Vibe Kanban закрывается, Conductor/Superset не видят чаты VS Code); GitHub merge queue (на личном приватном репо недоступна); помощники-отделы внутри одного чата (помощник не может запускать своих — пайплайну нужны критики и углы проверки); диспетчер-очередь вливания (вливает тот, кто закончил, замок файлом хватает); автономная реализация «до конца плана» (60 % остановок — настоящие вопросы, замер `~/.claude/forge-logs/plugin/execute-stops-integration.md`); `merge=union` в `.gitattributes` для YAML памяти (перемешает структуру; inbox закрывает причину, не следствие).

**Образцы из Прораба (`~/Downloads/Telegram Desktop/prorab.zip`):** ADR-0106 — один issue → один воркер/ветка, замок ставится ДО запуска, формат имени ветки один везде, протухшее снимается по времени; ADR-0078 — фрагменты в отдельных файлах вместо правки одного журнала, сборка скриптом при релизе, идемпотентно.

## Общие решения (чтобы шаги не спорили)

- **Папка состояния** (вне репо, видна всем копиям проекта): `~/.claude/forge-state/<ключ>/director/`, где `<ключ>` = путь основной папки проекта с `/`→`-` (как в `hooks/session-start.sh:61`), основная папка = `dirname "$(git rev-parse --path-format=absolute --git-common-dir)"` (так уже делает `codex-review.sh:24`, работает из любой копии). Внутри: `board.json` (доска), `board.lock/` (короткий замок на каждую правку доски — и у директора, и у `board.py`), `merge.lock/` (замок вливания).
- **Основная ветка** — `$BASE` как в finishing (`main` если есть, иначе `master`); слово «master» в скриптах не зашивать.
- **Доска меняется только через `board.py`** (`init` из файла, который директор написал во временную папку; `take/done/release`): каждая правка — прочитал → изменил → записал под `board.lock` (mkdir, ждать до 5 с). Директор напрямую `board.json` не пишет.
- **Чистая основная папка:** директор, записав память (`journal.d`, `direction.yml`), сразу коммитит её через `memory-backup/backup.sh` — иначе ff-вливание из отдела упрётся в его несохранённые правки. `.forge/state.yml` под игнором — не мешает.
- **Тесты — явное решение, не умолчание:** директор пишет в `board.json` поле `tests` — команду из `tests:` L0 или слово владельца «без тестов» (спросить одним вопросом, если строки `tests:` нет). Отдел без поля `tests` **не вливает** («директор не задал тесты — скажи ему»).
- **Копии проекта:** `.claude/worktrees/<отдел>/` на ветке `dept/<отдел>-<ГГГГ-ММ-ДД>` от master; создаёт отдел сам (`git worktree add … -b …`), входит через `EnterWorktree path=…`. `.claude/worktrees` — в `.git/info/exclude` (проверено: сейчас НЕ игнорируется).
- **Метка отдела:** файл `.forge/.department` в копии (одна строка — имя отдела). По нему скиллы понимают режим отдела. В `.forge/.gitignore`.
- **Память отдела:** `.forge/inbox/<slug>/` — схема каждого файла задана жёстко (шаг 2), журнал — как раньше, в `journal.d` (уникальные имена, конфликтов нет). Inbox коммитится в ветке (уезжает с ней), удаляется при складывании. `now:` в index.yml отдел **не трогает** (его ведёт директор в конце дня) — только `last_session:`.
- **Команда тестов проекта** — строка `tests:` в `.forge/index.yml` (L0); отсутствие — не «нет тестов», а вопрос директору владельцу (см. выше).
- **Один писатель общих файлов памяти** — тот, кто вливает, под замком, после слияния свежего master к себе.
- **Модели:** разведка директора — `forge:scout` (Haiku), всё остальное — как в `docs/model-roles.md`. Ничего нового.
- **Мера «по делу»:** никаких демонов, таймеров, браузера. Доска — текст по слову. Директор обновляется, когда ты его спросил (для автообновления есть встроенный `/loop 15m доска` — упомянуть в скилле одной строкой, не строить).

## Шаг 5: Тест и скрипт замка вливания

**Файлы:**
- Создать: `forge-plugin/tests/hooks/test-merge-lock.sh` — сначала красный
- Создать: `forge-plugin/skills/department/merge-lock.sh` — `take <кто>` / `release` / `status`; папка состояния — через `--state <dir>` (для тестов) или вычисляется из git

**Что делаем:** замок — `mkdir merge.lock` (атомарно), внутри `holder` (кто), `cwd` (копия держателя), `ts` (эпоха), `token` (случайный, печатается при взятии):
```bash
# take <кто> <cwd>: mkdir ok → записать, echo "LOCK: взят (<кто>) token=<t>"; занят → протух? нет → "LOCK: занято — вливает <holder> с <чч:мм>", exit 1
#   протух = возраст ≥ 90 мин ИЛИ в `claude agents --json` нет живой сессии с cwd держателя (claude недоступен → только по возрасту)
#   протух → снять и взять: "LOCK: снял протухший замок (<holder>, <N> мин, чата нет) — взят (<кто>)"
# release <token>: токен совпал → rm -rf; не совпал → "LOCK: чужой замок (<holder>) — не трогаю", exit 1; release --force — только по слову владельца «сними замок»
# status: свободен / занят кем, откуда и сколько минут
```
Тест (с поддельным `claude` в PATH): взять → второй take падает с «занято»; `ts` подменён на 2 часа назад → take снимает и берёт; `claude` показывает, что cwd держателя не живёт → снимает и без возраста; release с чужим токеном → отказ; со своим → status «свободен».

**Как проверим:** `bash forge-plugin/tests/hooks/test-merge-lock.sh` → PASS.

## Шаг 7: Тест и скрипт доски

**Файлы:**
- Создать: `forge-plugin/tests/hooks/test-director-board.sh` — сначала красный (поддельный `claude` в PATH, печатающий JSON как `claude agents --json`)
- Создать: `forge-plugin/skills/project-director/board.py` — stdlib, JSON

**Что делаем:** `board.py init <файл>|render|take|done|release [--state <dir>]`:
- `board.json`: `{date, project, base, tests, owner:[{text, kind}], departments:[{name, area, tasks:[{slug, title, done}], worktree}], contract:[…], notes:[…]}`; `init <файл>` — директор пишет такой JSON во временную папку, `init` проверяет форму (имена отделов уникальны, у каждой задачи slug, `tests` непустой) и кладёт в папку состояния
- каждая правка (`init/take/done/release`) — под `board.lock` (mkdir, ждать до 5 с, потом «BOARD: доска занята, повтори») → прочитал → изменил → временный файл + `os.replace`
- `take <отдел> <путь копии>`: `worktree` пуст → записать, `BOARD: отдел <имя> ведёт <путь>`; равен пути → **возобновление** («BOARD: отдел <имя> продолжает в <путь>»); другой путь → `BOARD: занято — отдел <имя> уже ведёт чат в <путь> (освободить: «освободи отдел <имя>»)`, rc=1.
