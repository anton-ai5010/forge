# План: три правила из Ponytail

**Задача:** см. `.forge/tasks/2026-10-17-ponytail-ideas.md`

**Подход:** Лесенка и пометки «упрощено» — текстом в меру «по делу» (`docs/delivery-bar.md`, единственное место с полным текстом), execute ссылается на неё. Нагрузка — новый пункт 0 чеклиста проверяющего; её определяет основной чат один раз за задачу и передаёт в промпт (Sonnet) и в task-файл (Codex получает тот же чеклист как промпт и сидит в пустой папке — README ему не виден). Пометки в гайде — решения группы `S` в `vX.Y.json`: render.py находит их `git grep` при каждой перерисовке, поэтому `verdict` работает без нового кода, а `link`/`merged` расширяются на решения.

**Что увидишь ты:**
- В отчёте execute строка «Сознательно не сделано» называет пометки в коде: «упрощено: … (`файл:строка`)».
- В гайде (05 «Решения») в конце, перед открытыми вопросами, — группа **S — Упрощено сознательно**: заголовок простыми словами, полный текст (что упрощено, когда начнёт мешать), строка «где: файл:строка». Нет пометок — группы нет.
- В «как работать с документом» (только если S есть) — фраза: «S — места, где сделано проще идеала, и известно, когда это начнёт мешать. Отвечать не нужно, пока не мешает. „S2 переделать“ (или „в работу“) — заведём задачу, „S2 обсудить“ — поговорим».
- S-пункты «оставляем как есть» не раздувают «ждут ответа» ни в гайде, ни в строке при старте сессии.
- Доделанное упрощение после мержа — «уже работает»; пометку просто убрали из кода — пункт уходит со страницы сам; вернули (откат, другая ветка) — возвращается с тем же кодом.
- В отчёте проверки строка «нагрузка: один владелец, бот на одном сервере (README)».

**Открытые вопросы:** нет.

**Блокеры:** нет. (Текущая ветка `feat/models-and-costs` уже влита в master — execute заведёт `feat/ponytail-ideas` от master.)

**Отложено в идеи:** сворачивать группу S при >7 пунктах — когда станет ясно, сколько пометок бывает на деле.

```markdown
## Перед тем как писать код — лесенка

Остановись на первой ступени, которая решает задачу целиком:
1. Нужно ли это вообще? Лишнее — не делаем, называем одной строкой.
2. Уже есть в проекте (функция, компонент, сервис, приём)? Берём, как берёт соседний код.
3. Стандартная библиотека языка?

5. Уже установленная зависимость? Новую ради пары строк не ставим.
6. Одна понятная строка?
7. Только потом — минимум своего.

Лесенка — после того, как прочитан код, который задача затрагивает, а не вместо этого. Ленимся в решении, не в чтении.

## Сознательное упрощение — пометка в коде

Рабочий код с известным пределом помечается одной строкой комментария (`#`, `//`, `--`, `/* */` — по языку):

`упрощено: <что упрощено> — переделать, когда <условие>`

Пишется для владельца-не-кодера: последствия простыми словами, без терминов. Текст уходит в гайд по проекту дословно (группа S).
- Хорошо: `# упрощено: список заказов грузится целиком — переделать, когда заказов станет больше ~5000 (страница начнёт открываться секунды)`
- Плохо: `# упрощено: без пагинации, N+1`

Пометка — не TODO: недописанный код, заглушка, «потом доделаю» пометкой не прикрываются — это по-прежнему «не сделано» из нижней планки.
```

`execute/SKILL.md`, в блок «Мера по делу» после строки «Спор»:
```markdown
- *Перед кодом* — лесенка из `delivery-bar.md`; сознательное упрощение рабочего кода — пометка `упрощено:` (формат и примеры там же).
```
Шаблон отчёта (`:239`): `**Сознательно не сделано:** [что и почему; пометки «упрощено» — с файл:строка; или «всё сделано»]`.

## Шаг 4: Сбор пометок в render.py

**Файлы:**
- Изменить: `forge-plugin/skills/project-guide/render.py`

**Что делаем:**
```python
SHORTCUT_GREP = r"(#|//|--|/\*)[[:space:]]*упрощено:"   # POSIX-класс: \s в git grep -E на маке не работает
S_TITLE = "Упрощено сознательно"
S_HOWTO = ("S — места, где сделано проще идеала, и известно, когда это начнёт мешать. "
           "Отвечать не нужно, пока не мешает. «S2 переделать» (или «в работу») — заведём задачу, «S2 обсудить» — поговорим.")

def scan_shortcuts():
    """[(file, line, text)] из git grep; None — не git / git сломан (тогда S не трогаем)."""
    try:
        r = subprocess.run(["git", "-c", "core.quotePath=false", "grep", "-n", "-I", "-E", SHORTCUT_GREP,
                            "--", ".", ":!*.md", ":!.forge"], capture_output=True, text=True, timeout=20)
    except (OSError, subprocess.TimeoutExpired):
        return None
    if r.returncode not in (0, 1):   # 1 = ничего не нашлось
        return None
    out = []
    for ln in r.stdout.splitlines():
        f, n, rest = ln.split(":", 2)
        text = rest.split("упрощено:", 1)[1]
        out.append((f, int(n), re.sub(r"\s*(\*/)\s*$", "", text).strip()))
    return out
```
`sync_shortcuts(data, today)` → True, если data менялась. Ключ `shortcut_key = f"{file}|{text}"`:
- найдено, есть решение → `source` (= `файл:строка`) и `why` (= `где: файл:строка`) обновить; если `status == dropped` и `dropped_by == "scan"` → `status: default`, убрать `dropped_by`, запись в `pending_changes` «S1 — пометка вернулась».
- найдено, нет решения → `S<max+1>` (max по всем S, включая dropped — номера не переиспользуются), `group: S`, `group_title: S_TITLE`, `title` = текст до « — переделать» (нет разделителя — весь текст), `what` = весь текст, `why` = `где: файл:строка`, `status: default`, `fire: False`, `source`, `shortcut_key`, `pending_changes` «S3 — новое упрощение».
- было, в коде нет → переводить в `dropped` + `dropped_by: scan` + `pending_changes` **только** если `status in ("default", "discuss")` и нет `task_slug`; `works`/`accepted`/`changed`/`dropped` и пункты с `task_slug` не трогать.
- `scan_shortcuts() is None` → ничего не менять.

Остальное:
- Вызов в `do_render` до `render_html`, только при `in_guide` и без `out_html`, в своём `try/except` (споткнулся → `print("FORGE-GUIDE: ⚠ пометки «упрощено» не собраны: …")`, рендер идёт дальше); изменилось → `save(jp, data)`. Итоговая строка вывода + «упрощений N» (не dropped).
- `groups()`: S не в `GROUP_BASE` (пустой группы нет); порядок `P` → буквы проекта → `S` → `O`.
- `render_howto`: если есть активные S → дописать `S_HOWTO`.
- `counts()`: `waiting` не считает решения группы S в статусе `default`.
- `link`: искать и в `decisions` по коду → `task_slug` (находки — как было).
- `merged`: решения с этим `task_slug`, статус не в ANSWERED → `status: works` + `pending_changes`.

**Как проверим:** `bash forge-plugin/tests/hooks/test-project-guide.sh` — все PASS (новые и старые).
