# План: Прокликай в браузере

**Задача:** см. `.forge/tasks/2026-10-24-browser-walkthrough.md`

**Подход:** Новый скилл `browser-walkthrough` — запускается только словами владельца. Путь берётся из критерия готовности задачи и превращается в 3–8 шагов «открыть / нажать / ввести → должно быть видно». Своё (localhost, свои HTML) проходит помощник Sonnet в невидимом Playwright, живой сайт — основной чат в Chrome владельца (DEC-27). Опасное (оплата / отправка / удаление) — «Стоп: …? да/нет» **везде**, не только на живом сайте. Сломанное своё чинит основной чат и проходит заново, не больше 3 кругов; на живом сайте — причина и правка, повтор только после выката. Снимки собирает в одну страничку маленький скрипт `shots-page.py` (картинки внутри файла, открывается без сервера). Запуск проекта: подход встроенного `run` (скилл запуска проекта → его команда), но сам `run` не зовём — он открывает свой браузер; свой HTML — `python3 -m http.server` (Playwright не открывает `file://`). В финальный отчёт execute — подсказка одной строкой.

**Что увидишь ты:**
- Пишешь «прокликай» — Claude проходит страницу по критерию задачи. По ходу строки «иду по странице: 5 шагов, пара минут», «круг 2 из 3: чиню кнопку „Сохранить“»; в конце — «прошёл в браузере: 5 шагов, всё работает» (или «нашёл и починил: …»).
- Страничка со снимками сама открывается в браузере: 3–5 картинок с подписями «1. Открыл форму», «2. Заполнил»… Через удалённый доступ — присылается файлом, лёгкая, открывается на телефоне.
- Перед оплатой / отправкой / удалением — «Стоп: …? да/нет», где бы ни была страница; созданные тестовые записи перечислены в итоге.
- Не смог начать (не запустилось, Chrome не подключён, сайт просит войти) — простая строка, что мешает и что сделать тебе; «прошёл» в таком случае не пишет.
- В конце задачи, которая меняла страницы, строка: «Можно прогнать в браузере — скажи „прокликай“». Сам не запускает.
- Решение, которое стоит поправить сейчас: как выглядит страничка снимков — покажу набросок первым шагом.

**Что уже выяснено:**
- Встроенный `run` (Claude Code 2.1.309, текст из бинарника): сначала ищет скилл запуска в `.claude/skills/*` проекта, иначе шаблон по типу проекта; для веба — dev-сервер + `chromium-cli` (свой браузер — поэтому сам `run` не зовём, берём только способ найти команду запуска). Пути из критерия, правил опасного, починки с повтором, отчёта владельцу в нём нет — это и добавляем.
- Playwright MCP: `file://` запрещён; с `PLAYWRIGHT_MCP_HEADLESS` / `ISOLATED` (DEC-27) — невидимый, у каждого свой профиль; снимки по умолчанию ложатся в `<папка чата>/.playwright-mcp/`.

- Таблица обновлений (`.forge/conventions.yml` → `update_map`): новый скилл → `CLAUDE.md`, `using-forge/SKILL.md`; версия → три json.

**Тест:**
```bash
#!/bin/bash
# shots-page.py: страничка снимков прохода «прокликай»
ROOT="$(cd "$(dirname "$0")/../.." && pwd)"; S="$ROOT/skills/browser-walkthrough/shots-page.py"
T=$(mktemp -d); trap 'rm -rf "$T"' EXIT; fails=0
check() { if eval "$2"; then echo "✓ $1"; else echo "✗ $1"; fails=$((fails+1)); fi; }
python3 -c "import base64,sys;d=base64.b64decode('iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mNk+M9QDwADhgGAWjR9awAAAABJRU5ErkJggg==');[open(f'$T/{n}','wb').write(d) for n in ('1.png','2.jpg')]"
python3 "$S" "$T/logs/out.html" "Форма заказа — всё работает" "$T/1.png::Открыл <b>форму</b>" "$T/2.jpg::Нажал «Отправить»" >/dev/null
check "собрал страничку" "[ -s '$T/logs/out.html' ]"
check "две картинки внутри файла" "[ \$(grep -oE 'src=\"data:image/(png|jpeg);base64,' '$T/logs/out.html' | wc -l) -eq 2 ]"
check "jpg — с типом jpeg" "grep -q 'data:image/jpeg;base64,' '$T/logs/out.html'"
check "подписи экранированы" "grep -q 'Открыл &lt;b&gt;форму&lt;/b&gt;' '$T/logs/out.html'"
check "заголовок на месте" "grep -q 'Форма заказа — всё работает' '$T/logs/out.html'"
check "файл только владельцу (600)" "[ \$(stat -f %Lp '$T/logs/out.html') = 600 ]"
check "папка только владельцу (700)" "[ \$(stat -f %Lp '$T/logs') = 700 ]"
python3 "$S" "$T/bad.html" "x" "$T/нет.png::y" 2>/dev/null; rc=$?
check "нет снимка → код 1, файла нет" "[ $rc -eq 1 ] && [ ! -e '$T/bad.html' ]"
python3 "$S" 2>/dev/null; check "без аргументов → код 2" "[ $? -eq 2 ]"
echo; [ $fails -eq 0 ] && echo OK || { echo "$fails FAIL"; exit 1; }
```

**Код:** вёрстка — из одобренного наброска (шаг 1), картинки — `data:` URI (тип по расширению: `.png` → png, `.jpg`/`.jpeg` → jpeg), подписи — `html.escape`; аргументы `<out.html> <заголовок> <снимок>::<подпись>…`; папку странички создаёт с правами 700, файл пишет с правами 600 (на ней могут быть аккаунты владельца); нет файла снимка → stderr «нет снимка: …», код 1, ничего не пишет; страничка тяжелее 3 МБ → предупреждение в stderr «страничка N МБ — на телефоне может не открыться»; печатает путь странички.

**Как проверим:** тест падает до скрипта (`No such file`) → после — `OK`.

## Шаг 3: Скилл `browser-walkthrough`

**Файлы:**
- Создать: `forge-plugin/skills/browser-walkthrough/SKILL.md`

**Frontmatter:**
```yaml
---
name: browser-walkthrough
description: "Use ONLY when the user explicitly asks to walk a web page in a browser like a user. RU: 'прокликай', 'проверь в браузере', 'пройди как пользователь', 'прогони в браузере', 'потыкай страницу'. EN: 'click through', 'walk through in the browser', 'test it like a user'. Walks the path from the current task's completion criterion (open / click / fill → expected result), fixes what is broken and walks again (max 3 rounds), reports one line + a page with 3–5 screenshots. NOT automatic: never after code steps or at the end of execute on its own — execute only suggests it with one line."
---
```

**Содержание (разделы):**
1. **Путь** — задача из `.forge/state.yml` (`task:`) или ветки `feat/<slug>` → `.forge/tasks/*-<slug>.md`, `## Критерий готовности` → 3–8 шагов «действие → что должно быть видно»; задачи нет — путь из слов владельца. Пункты критерия без страницы (настройки, скрипты) — пропустить и назвать в итоге. В чат — строка «иду по странице: N шагов, пара минут».
2. **Где** — localhost / свой HTML / dev-сервер → «своё»; домен в интернете → «живой сайт».
3. **Опасное — везде** — оплата / покупка, отправка от имени владельца или наружу (письмо, сообщение, заказ), удаление, загрузка файла: перед последним кликом «Стоп: <что> на <адрес>? да/нет» — и на localhost тоже (местная программа может работать с настоящими данными и ключами). Правило из `~/.claude/CLAUDE.md`, адрес его не отменяет.
4. **Запуск своего** — адрес не отвечает: скилл запуска проекта (`.claude/skills/*/SKILL.md` с описанием запуска) — взять из него только команду запуска сервера; нет — скрипт `dev`/`start` из `package.json` и т.п.; свой HTML — `python3 -m http.server <порт> --bind 127.0.0.1` из папки страницы. Встроенный Skill `run` не вызывать — он открывает свой браузер. Сервер — фоном; остановить то, что поднял сам, после прохода.
5. **Своё — помощник** (`docs/model-roles.md`): Agent `model: "sonnet"` (general-purpose), промпт: адрес + шаги пути + «только `mcp__plugin_playwright_playwright__*` / `mcp__playwright__*`; Playwright недоступен или не отвечает — сразу верни „заблокировано: Playwright“, Chrome (`mcp__claude-in-chrome__*`) не трогай; на каждом шаге — что видно, ошибки консоли (`browser_console_messages`); опасную кнопку (п. 3) не нажимай — верни „⏸ <что> на <адрес>“; созданные записи — список с тестовыми данными (метка `тест-<ЧЧММ>`); 3–5 снимков ключевых моментов `browser_take_screenshot` `type: "jpeg"`, `filename` — абсолютный путь в `<папка>`, если инструмент вернул другой путь — верни его; код не правь; ответ ≤ 25 строк: шаг — ✅/❌/⏸ — что видно — путь снимка». ⏸ → основной чат спрашивает владельца «Стоп: …», на «да» — новый помощник с разрешением ровно на это действие.
6. **Живой сайт — основной чат**, Claude in Chrome: `tabs_context_mcp` → своя вкладка; нажимать можно всё, кроме п. 3; каждая созданная запись — в список «тестовые записи»; снимки — `computer screenshot save_to_disk`, путь — тот, что вернул инструмент.
7. **Не смог начать / заблокировано** — отдельный исход, код не трогать, «прошёл» не писать, одна строка владельцу простыми словами: не запустилось (что выдала команда запуска) · Chrome не подключён → «нажми значок Claude в Chrome» · сайт просит войти → «Стою на странице входа <сайт>. Войди сам в этой вкладке и скажи „готово“» · Playwright недоступен → «невидимый браузер не отвечает — проверить своё не могу», в Chrome владельца не переходить.
8. **Сломано → починка** — ❌ на шаге: причина по `systematic-debugging` (без угадывания), правка, новый полный проход; в чат «круг N из 3: чиню <что>». Перед повтором — список созданного прошлым проходом: шаги, создающие записи, — с новыми тестовыми данными, необратимое — снова «Стоп». Не больше 3 кругов; не вышло — итог «не починил: <что>, причина: <что знаю>», без «готово». На основной ветке (задача уже влита) — перед правкой молча `git checkout -b fix/<slug>-walkthrough`, после — предложить «мержим». **Живой сайт:** правка в коде на сайт сама не попадает — причина + правка в коде (если это проект владельца), повтор только после выката по слову владельца; итог «на сайте не починено до выката: <что>».
9. **Страничка** — `python3 $CLAUDE_PLUGIN_ROOT/skills/browser-walkthrough/shots-page.py ~/.claude/forge-logs/<проект>/walkthrough-<ГГГГ-ММ-ДД-ЧЧММ>.html "<итог>" <снимок>::<подпись>…` → `open` её; в чат — ссылка `[страничка снимков](file://<абсолютный путь>)`; владелец не у компьютера (удалённый доступ) — SendUserFile. Снимки после сборки удалить (и из `.playwright-mcp/` проекта, если легли туда).
10. **Итог в чат** — 2–4 строки: «прошёл в браузере: N шагов — всё работает / нашёл и починил: … / не смог начать: …», ссылка на страничку, тестовые записи (или «не создавал»), пропущенные пункты критерия.
