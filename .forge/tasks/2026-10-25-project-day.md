# День проекта: один день — один проект, отделы параллельно, к вечеру — в main

## Задача
Режим «День проекта»: один день — один проект. Диспетчер (один чат, скилл) выкладывает все незакрытые дела проекта, делит на отделы по территории в коде, утром фиксирует общие форматы («фундамент»); отделы — обычные чаты, которые владелец заводит строкой от диспетчера; каждый работает в своей копии проекта теми же фазами и проверками, вопросы собирает владельцу пачкой, готовое вливает в main сам, по одному, под замком, с тестами. Качество — как в обычном пайплайне.

Сначала — **минимум для пробного дня** (5 вещей ниже), пробный день на плагине (5 отделов — решение владельца 2026-10-25) как замер, и только потом — то, чего в пробном дне не хватило (браузерная доска, отдельные тестовые данные для integration и т. п.).

Откуда: direction.yml → «День проекта» (2026-10-24), временная карта integration (`~/.claude/forge-logs/plugin/integration-timeline.md`), список 34 незакрытых дел integration (из них ~12 работы Claude, 8 ждут слова владельца, 8 — чужих людей), разбор остановок execute в integration за 14 дней (`~/.claude/forge-logs/plugin/execute-stops-integration.md`: 60 % настоящих вопросов, 36 % ритуальных «Окей, продолжать?»).

## Критерий готовности
Минимум для пробного дня:
- **Диспетчер.** «День проекта» в проекте с `.forge/` → один список: отдельно **дела владельца** (решения, невлитые ветки, письма людям) и **работа Claude** по отделам (территория в коде по карте проекта; связанные задачи — в один отдел, по очереди); у отдела — строка для нового чата; утром диспетчер фиксирует общие форматы/поведение, которые трогают несколько отделов («фундамент»), — до старта отделов. Доска v1 — текст/файл, который отделы обновляют при смене состояния; браузер — после пробного дня
- **Отдел.** Вставил строку → чат сам уходит в свою копию проекта, ставит все свои задачи, независимые вопросы сдаёт пачкой (зависимые — после ответов), пишет своё состояние («работаю / жду тебя: о чём / готово») в файл состояния; владелец отвечает в чате отдела
- **Память без драк.** Отдел пишет решения / тупики / уроки / статус / `now` в свой файл `.forge/inbox/<slug>.yml`, общие файлы не трогает; при «мержим» под замком складывает их в общие файлы (коды DEC-NN, перечитка свежей памяти перед слиянием, повтор безопасен, противоречие — владельцу)
- **Вливание.** По слову владельца «мержим»: один общий замок в основной папке (с именем владельца и снятием после обрыва) → свежий main к себе в ветку → тесты → только потом main обновляется; сломалось — чинит тот, кто вливал; недоделанное вечером сохраняется, не убирается
- **Реализация без ритуала.** В execute между шагами нет «Окей, продолжать?» / «Если ОК — запускаю»: если проверка шага прошла — идёт дальше; останавливается только на чекпоинте плана, на решении владельца, на действии на бою (выкат / слияние / удаление / отправка) и на факте, который знает только он
- Деньги / прод / удаление — стоп всегда

Пробный день (замер, не код):
- Плагин, 5 отделов (слово владельца), руками через минимум выше; замер: сколько задач дошло до main, сколько раз и о чём владелец отвечал, где схема упала; результаты — в `.forge/notes/project-day-trial.md`, и только по ним — следующий шаг
- До пробного дня владелец сам разбирается в integration, почему 454 коммита не доходят до main, — причины записать: их и должен чинить режим

## Доработано на разборе (2026-10-25, Claude + Codex GPT-6 Astra)
- Выигрыш — в двух дешёвых вещах (вопросы пачкой, готовое сразу в main) + параллельность отделов; строим минимум, остальное после замера (Codex: «не ускорить создание завала»)
- Разные файлы ≠ независимость: общие форматы фиксирует диспетчер утром; связанные задачи — последовательно в одном отделе
- Проверять main после вливания поздно → свежий main к себе → тесты → main; замок общий, с владельцем и восстановлением
- Копии проекта делят `.env` → в integration параллельные тесты могут пойти в боевые сервисы; для плагина не актуально, для integration — отдельные тестовые данные до его дня проекта (после пробного)
- Автономность execute «до конца плана» отвергнута: 60 % остановок — настоящие вопросы; убираем только 36 % ритуальных
- Оценки (±50 %): ~2,5 ч работы Claude на задачу; 12 задач integration тремя отделами — ≥10 ч без слияний; «один день» — обещание до замера
