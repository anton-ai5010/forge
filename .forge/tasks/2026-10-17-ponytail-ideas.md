# Три правила из Ponytail

Источник: github.com/dietrichgebert/ponytail — `skills/ponytail/SKILL.md` (лесенка, `shortcut:`-пометки), `skills/ponytail-review/SKILL.md` (ожидаемая нагрузка). Сам Ponytail не ставим: второй постоянно включённый набор правил конфликтует с пайплайном, TDD «тест сначала падал» и Output Style.

## Задача
Перенести из Ponytail в плагин три правила: лесенку «сначала готовое, потом своё» перед написанием кода; оценку ожидаемой нагрузки проекта при проверке кода; пометки сознательных упрощений в коде, которые собираются в раздел гайда по проекту с кодами для ответа владельца.

## Критерий готовности
- В `forge-plugin/docs/delivery-bar.md` — лесенка: нужно ли вообще → уже есть в проекте → стандартная библиотека → встроено в платформу → установленная зависимость → одна строка → только потом минимум своего. Execute на шагах с кодом идёт по ней.
- Проверяющий в пункте «перебор?» (`skills/requesting-code-review/review-checklist.md`) ловит своё там, где было готовое («написал своё, а в проекте уже есть X» — находка).
- Проверяющий сначала пишет одной строкой, под какую нагрузку судил и откуда взял (README, настройки запуска), и оценивает гонки/скорость под неё; эта строка — в итоге каждой проверки.
- Сознательное упрощение execute помечает в коде комментарием одного формата (что упрощено, предел, когда переделать) — только на рабочем коде с известным пределом; строка «Сознательно не сделано» в отчёте ссылается на пометки. Пометка на недоделанном (заглушка, TODO под другим именем) — находка проверяющего.
- Буква `S` в гайде закреплена за упрощениями наравне с P/O/R (`docs/project-guide-format.md`): под проект её не подбирают.
- Пометки собираются поиском по коду при каждой перерисовке гайда (render, verdict, merged — без помощников), не только при полной сборке; все попадают в раздел «Упрощено сознательно» с кодами S1, S2…; ответ «S2 — переделать» обрабатывается как другие коды (`render.py verdict`), пункт можно увести в new-task (`render.py link`).
- Живая проверка: тестовый проект с 2 пометками → гайд показывает 2 пункта S, ответ на S-код меняет статус; новая пометка появляется в гайде после `render.py merged` без полной сборки; тесты плагина (`forge-plugin/tests/hooks/`) зелёные.

## Доработано на разборе
- `S` закреплена за упрощениями (буквы групп в гайде подбираются под проект — иначе коллизия); сбор пометок механический при каждой перерисовке, а не только при полной сборке (6 помощников).
- Пометка «упрощено» — только на рабочем коде с пределом; на недоделанном — находка (не размываем правило «нет заглушек и TODO» из delivery-bar).
