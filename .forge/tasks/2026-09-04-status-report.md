# Отчёт «Что дальше» — Фаза 5 плагина (status-report)

## Задача
Добавить в плагин отчёт «Что дальше» — HTML-документ по формату `forge-plugin/docs/status-report-format.md`: в каком состоянии проект, что чинит Клод в коде, какие решения нужны от владельца, в каком порядке и почему. Полная сборка — по команде (с аудитом проекта параллельными агентами), лёгкое обновление — само после каждого влитого мержа. Читается как файл на Маке (без публикации по ссылке). Выпустить как новую версию плагина на GitHub.

## Критерий готовности
- Есть команда `/forge:status-report` и слова-триггеры («собери отчёт», «отчёт „что дальше“», «что чинить, что решать», «покажи документом, где мы»): Клод прогоняет аудит проекта (код + память `.forge`, несколько агентов параллельно), собирает HTML-отчёт по формату и открывает его в браузере. Слова «что дальше по проекту» и «статус проекта» остаются за навигатором и загрузкой контекста — отчёт на них не перехватывается.
- HTML не пишется Клодом вручную: находки лежат в файле данных, страницу из них собирает скрипт-рендерер (без внешних библиотек). Опечатка в тексте находки не ломает вёрстку.
- Отчёт держит формат-эталон: «Главное одной фразой» наверху, 2–4 блока по оси «владелец × срочность», карточки с чипом «Код / Решение / Решение+код», бейджем усилий S/M/L, «Что / Зачем», футер с честными числами (N находок → M блоков, K отложено), от первого лица, без жаргона.
- Если у проекта есть запущенный интерфейс в браузере — в карточки про интерфейс вставлены снимки экрана (не больше 6, встроены прямо в HTML); если снимать нечего или снимок не удался — отчёт собирается без картинок, без ошибок и без вопросов владельцу. Служебные файлы браузера (папка `.playwright-mcp/`, снимки в корне проекта) в проекте не остаются.
- После «мержим» (влитой задачи) отчёт обновляется сам без нового аудита: карточка задачи уходит в «сделано», дата и счётчики пересчитываются, HTML перезаписан.
- Данные отчёта (находки, владелец, усилия, статус, открытые решения) лежат в памяти проекта `.forge` и переживают сессию: при старте новой сессии Клод одной строкой напоминает, сколько решений ждут владельца и на сколько влитых задач отчёт устарел.
- Отчёт — единственный документ «где мы» для владельца: навигатор `/forge:unblocker` больше не заводит `ROADMAP.md`, а отсылает к отчёту.
- Фаза 5 описана везде, где перечислены фазы плагина (README, CLAUDE.md, COMMANDS.md, session-start, statusline, шаблон init, evals); версия поднята до 7.7.0; ветка влита в master и запушена — на GitHub в master лежит `plugin.json` с версией 7.7.0.

## Решения, принятые Клодом (владелец может отменить)
- Отчёт — на Маке как файл, а не страница по ссылке (выбор владельца).
- Скриншоты — только когда есть что снимать (выбор владельца).
- Полная сборка по команде + лёгкое обновление после мержа (выбор владельца, вариант 3).
- `ROADMAP.md` из навигатора убираем: два документа «где мы» для одного человека — путаница; в проектах владельца `ROADMAP.md` ещё ни разу не создавался, менять дёшево.
- Открытые «Решения» копятся в памяти и напоминаются одной строкой при старте сессии; Клод спрашивает по одному только по слову владельца, сам работу не двигает (карточки «Код» — через `/forge:new-task` по выбору владельца).
- На GitHub отчёт не отражается (ни лейблов, ни Issue) — он живёт в памяти проекта и уезжает туда вместе с ней при сохранении.

## Доработано на разборе
- Страницу собирает скрипт из файла данных, а не Клод руками: в плагине уже был урок — карта проекта перешла на «данные + шаблон», чтобы страницы не ломались. Заодно обновление после мержа становится механическим шагом (пометить карточку → пересобрать).
- Триггеры разведены с навигатором и загрузкой контекста: «что дальше по проекту» и «статус проекта» уже заняты, отчёт откликается на «собери отчёт» и похожие.
- Скриншоты — только «по возможности»: неудача снимка не останавливает отчёт, мусор браузера убирается.
