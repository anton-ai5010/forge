## 1. Что сейчас в плагине с моделями
- Модель указана только у `agents/forge-documenter.md` и `agents/structure-enforcer.md` (sonnet). `agents/code-reviewer.md` — `inherit`. Критики, сборщики гайда, навигатор, product-mapping, помощники execute — без модели → наследуют модель основного чата (Opus/Fable).

## 2. Разбор расходов integration (по ценам API, приблизительно)
- 12 основных чатов, 78 одиночных помощников, ~650 помощников в 60 воркфлоу. Итого ≈ **$3 300**.
- **~62% — воркфлоу**: модель не указана → когда основной чат был на Fable, короткие проверялки («проверка:skeptic/advocate/architect», «verify:trace/refute», 6–8 шагов) шли на Fable ≈ **$490**.
- **~32% — основной чат**: средняя память на шаг **400–700 тыс. токенов** (длинные сессии, тысячи выводов Bash копятся и перечитываются).
- Структура затрат: перечитывание кеша ~52%, запись в кеш ~36%, ответы ~12%.
- **Неочевидное**: у Sonnet 5.5 чтение кеша стоит как у Opus 5.5 ($0.20/M) → Opus→Sonnet экономит ~40%, а не в разы; Fable→Sonnet ~80%. Главный рычаг — размер памяти основного чата.
- Сон чатов: «разбудить» чат, простоявший дни (кеш ~1 ч), = перезалить всю его память по полной цене (≈$2–3 на 500k у Opus).

## 3. Тест локальных моделей (мак M5 Pro 48 ГБ, Ollama 0.40.3)
17 настоящих длинных выводов терминала из integration, задача «сожми до важного», слепая оценка тремя судьями Opus (1–5):

| Модель | Качество | Неверных фактов | Лучший в N из 17 | Время/пример |
|---|---|---|---|---|
| Qwen 3.8 27B (локально) | **3.88** | 14 | 12 | ~43 с |
| Haiku 4.5 | 3.47 | **31** | 6 | ~16 с |
| Qwen 3.6 35B (локально) | 3.06 | 24 | 3 | ~8 с |
| Gemma 4 26B (локально) | 2.94 | 11 | 4 | ~10 с |

- Ни одна не держит 5/5 → пересказ лога = подсказка, сырой вывод должен оставаться доступен.
- 4070 Ti на PC1 (12 ГБ) Qwen 3.8 не вместит — мак лучше.
- Выгода локальной модели — не деньги (Haiku ≈3 цента за лог), а **качество** и то, что лимит Claude не тратится вовсе. Haiku лимит подписки тратит (меньше Opus; точное соотношение не публикуется).
- Решение: сжиматель логов = Qwen 3.8 если есть Ollama, иначе Haiku; плагин не зависит от локальной модели. Gemma 4 и Qwen 3.6 можно удалить (~40 ГБ) — не удалены, ждут слова Антона.

## 4. Jev (TypeSafe, через OpenRouter)
- Модель-«решатель»: возвращает выбор/да-нет + уверенность (при ≥0.9 права в 94–96% — по их данным), быстрая и в ~100 раз дешевле Opus, контекст 32k.
- **Не используем для выбора модели помощникам** (Opus видит контекст и выбирает лучше; лишняя задержка и точка отказа).
- **Кандидат для выбора скилла**, когда скиллов станет 100–200: «склад» скиллов вне списка Claude Code + хук с Jev + подсказка Opus при высокой уверенности, иначе Opus выбирает сам. При 200 скиллах описания ≈40k токенов > 32k у Jev → короткие выжимки по ~80 токенов.
- Сейчас 35 скиллов, описания ≈6–8k токенов, кешируются — экономия копеечная.

## 5. Codex (подписка ChatGPT)
- `codex exec -s read-only` работает с подпиской (MCP-подключение Codex в Claude Code сейчас падает — не нужно).
- Роли: **ревьюер другой семьи** (ошибки GPT и Claude мало коррелируют — лучше схемы «Sonnet проверяет Opus») и **второе мнение** на трудных местах; запасной исполнитель при кончившемся лимите — только в отдельной копии проекта.

## 6. Другие чаты, effort, ultracode
- Claude может писать в другие открытые чаты (ListAgents/SendMessage; у Антона 16 открытых), но **не может создать новый**. Писать в другой чат выгодно, только если он недавно активен или задача его проекта; иначе — помощник.
- `claude -p` — отдельная фоновая сессия; Daintree MCP позволит открывать **видимые** новые чаты-агенты.
- Effort помощникам Claude выбирает сам (воркфлоу: `effort` у каждого агента; одиночные — через типы агентов). Effort основного чата меняет только Антон (`/effort`) — плагин подсказывает: разбор/план/критика — high, реализация по плану — medium, мелочи — low.
- Ultracode включает только Антон; он не экономит, а наоборот — режим максимального качества для важных задач. Плагин может предложить.

## 7. Прораб (github martadvix-web/prorab; у нас старая версия из Telegram)
Самохостная платформа: агенты-роли на сервере, задачи из GitHub Issues, человек только одобряет в конце, Telegram + веб-панель, свой LLM-роутер, пул подписок Claude. Автор пользуется forge только для карты/графа кода.
**Берём:**
- таблица роль→модель с «почему» (`core/config.py:289-315` `_MODELS`);
- роль-извлекатель на Haiku (`core/commitments/extraction.py`);
- уборщик памяти с правилами ХРАНИТЬ/СЖАТЬ/ВЫБРОСИТЬ, самопроверкой и «сомневаешься — оставь» (`prompts/groomer.md:24-109`, ADR-0030);
- жёсткая проверка перед «готово» хуком (ADR-0038) — у нас пока только текст в скилле;
- ревью другой моделью (ADR-0005: ошибки автора и ревьюера одной модели коррелируют);
- учёт расходов по ролям (у нас — разбором логов чатов, без записи на лету);
- промпты ролей: ревьюер (9-пунктный чеклист, «проверено: OK/нашёл» по каждому, Fix к каждой проблеме — `prompts/reviewer.md:29-39,79-91`), отчёт исполнителя ГОТОВО/ЗАБЛОКИРОВАН + «как проверял / что не сделано» (`developer.md:194-247`), тестер «не тестировал / регресс соседей» (`tester.md:38-94`), devops pre-flight + ≤5 попыток + журнал ручных действий на проде (`devops.md:59-121`), архитектор «рассмотрели и отвергли» (`architect.md:35-63`);
- golden-тесты промптов по вызовам инструментов (`tests/prompts/golden/*.yaml`) — образец для пустой `evals/`; не повторять их промахи (snapshot молча пропускается, фикстура 005 подсказывает ответ);
- git: замок «одна задача — одна ветка — один исполнитель» (ADR-0106), записи памяти отдельными файлами-фрагментами (как `changelog.d`, ADR-0078), защитный коммит при завершении сессии, уборщик осиротевших веток/копий.
**Не берём:** серверный рантайм (SQLite, оркестратор, Flask, RBAC), свой LLM-роутер, пул подписок, обязательный PR+approve, worktree на каждого, номера issue в ветках, серверный деплой.
**Где сильнее forge:** TDD, «без вывода команды не говорить готово», spec-reviewer «не верь отчёту», 4 критика, чекпоинты и журнал отклонений, загрузка памяти по тегам, простой язык.
**Неточность, найденная при проверке:** правило `session-awareness/SKILL.md:92` «записей >7 — удали самые старые» касается только журнала сессий, а не уроков; удалённое остаётся в git-истории → это неудобство, а не потеря.

## 11. Документация: Прораб vs forge
**Прораб:** документация в репо рядом с кодом, пишут агенты и человек по одним правилам (`CONTRIBUTING.md`): карта «один факт — одно место» (:216-244), **иерархия правды** код > тесты > CONTRACTS/ARCHITECTURE > ADR > BRIEF > DEVLOG (:245-257), таблица «что изменил → что обновить» (:258-), BRIEF как живой контракт с разделом «§9 расхождения с кодом» (`BRIEF.md:126,147-156`), ~120 ADR («Superseded», не удаляются), RUNBOOK 6452 строк, CONTRACTS 3209, OPSLOG, changelog-фрагменты, машинный doc-gate в CI (`ci.yml:208-250` — проверяет только «файл тронут»), раздел «Не делать» в `prompts/contexts/prorab/memory.md:15-19`. **Дрейф всё равно есть** (их аудит: README/VISION про SvelteKit при vanilla SPA, ARCHITECTURE отстаёт на 13 миграций, VISION/ROADMAP не обновлялись с апреля) → правила без проверки фактов не держат.
**forge:** L0 `index.yml` (хук, режется до 2500 байт — `hooks/context-inject.sh:17-20`) → L1 по тегам → L2 library; гайд для человека с кодами решений; dead-ends и direction. Нет автопроверки «код изменён, доки нет»; hard rules только текстом.
**Берём (в задачу «Порядок в памяти» и пункт backlog про документацию):**
1. автопроверка дрейфа фактов (число скиллов в CLAUDE.md 33 vs 35, мёртвые ссылки на lib/ в map/conventions) — в `/forge:validate` или хук; сначала предупреждение;
2. короткие «где какая правда» + «иерархия правды» (код > память > старый журнал; один факт — одно место, иначе ссылка);
3. таблица «что изменил → что обновить» для плагина (скилл → CLAUDE.md, хук → tests/hooks, команда → Commands Reference) в conventions + промпт ревьюера;
4. раздел «известные расхождения» с датой в status/map;
5. стабильные коды решений D-NN (грузить одну запись по коду; «заменено решением D-X» вместо удаления);
6. блок «Не делать» в начале index.yml, чтобы не отрезался обрезкой 2500 байт;
7. оглавление вместо целых файлов (как индекс ADR);
8. для владельца: в гайде и строке старта сессии — «расхождений код/доки: N», «доки без правки N дней»;
9. журнал записями-фрагментами (параллельные чаты без конфликтов).
**Не берём:** десятки огромных доков (наш путь — малое и по тегам), нумерацию ADR по issue и CI-скрипты, «ADR на каждую мелочь», doc-gate «файл тронут» как единственную защиту, флаг «обойти всё».
